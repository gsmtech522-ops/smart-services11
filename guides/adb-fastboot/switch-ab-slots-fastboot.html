How to Switch A/B Slots in Fastboot & Fix Slot Change Errors

Type
Step-by-Step Guide
Level
Intermediate
Time
~5 minutes
Applies to
All A/B seamless-update Android devices (Android 7+)
Last updated
YYYY-MM-DD

Modern Android devices use an A/B (Seamless Update) partition structure. Instead of one set of system partitions (boot, system, vendor), these devices have two identical copies — Slot A and Slot B. While one slot runs the active OS, updates are installed quietly to the inactive slot in the background.

If a firmware flash fails, an update causes a bootloop, or the device gets stuck after flashing a boot image, manually switching the active slot via Fastboot can immediately recover the device without wiping data.

Reference

  1. 1. Prerequisites

    • ADB & Fastboot installed on PC.
    • Device booted into Fastboot / Bootloader mode.
    • Unlocked bootloader — required for manual slot changes.

  2. 2. Step 1 — Check the current active slot

    Before any change, verify which slot the device is configured to boot from:

    1. Open Command Prompt in your Fastboot directory.
    2. Run:
    fastboot getvar current-slot

    Output is either current-slot: a or current-slot: b.

    If the command errors with "unknown variable", your device is A-only (no A/B slots) — slot switching is not supported. Skip to troubleshooting error 2.

  3. 3. Step 2 — Switch the active slot

    Switch to Slot A:

    fastboot set_active a

    Switch to Slot B:

    fastboot set_active b

    Older Fastboot versions (alternative syntax):

    fastboot --set-active=a

    On success, terminal reports: Setting current slot to 'a'... OKAY

  4. 4. Step 3 — Reboot and test

    fastboot reboot

    If the alternate slot boots correctly, your device is recovered — no data loss.

  5. 5. Troubleshooting slot change errors

    Error 1: FAILED (remote: 'slot change is not allowed in Lock State')

    Cause: bootloader is locked. Security policies prevent partition changes on locked bootloaders.

    Fix:

    fastboot flashing unlock

    Data wipe warning: unlocking the bootloader wipes all userdata. Back up first if possible.

    Error 2: FAILED (remote: 'Slot-count is 0') or "Device does not support slots"

    Cause: device is A-only (traditional single-partition structure), not A/B.

    Fix: do not attempt slot switching. Flash directly to standard partitions:

    fastboot flash boot boot.img

    Error 3: FAILED (remote: 'invalid slot name')

    Cause: uppercase letters or invalid characters in the command (e.g. Slot_A, A).

    Fix: always use single lowercase — a or b.

    Error 4: Device stuck in Qualcomm CrashDump or bootloop after slot switch

    Cause: the inactive slot you switched to contains corrupt, empty, or incompatible firmware.

    Fix: re-enter Fastboot (Volume Down+Power) and switch back to the working slot:

    fastboot set_active a

    Then flash the alternate slot's boot image with correct firmware.

  6. 6. Advanced — flash to a specific slot directly

    You can target partition slots explicitly without switching the active slot first:

    fastboot flash boot_a boot.img
fastboot flash boot_b boot.img
fastboot flash system_a system.img
fastboot flash system_b system.img
fastboot flash vbmeta_a vbmeta.img
fastboot flash vbmeta_b vbmeta.img

    Why flash both slots? if the other slot's boot/system is corrupt, the device will bootloop if you ever switch to it. Flashing both slots keeps them in sync.

  7. 7. Complete command reference

    # ---- Enter Fastboot ----
adb reboot bootloader
fastboot devices

# ---- Check current slot ----
fastboot getvar current-slot

# ---- Switch slots ----
fastboot set_active a
fastboot set_active b

# ---- Older syntax ----
fastboot --set-active=a
fastboot --set-active=b

# ---- Reboot ----
fastboot reboot

# ---- Flash to specific slot without switching ----
fastboot flash boot_a boot.img
fastboot flash boot_b boot.img
fastboot flash system_a system.img
fastboot flash system_b system.img
fastboot flash vbmeta_a vbmeta.img
fastboot flash vbmeta_b vbmeta.img

# ---- Check slot-related variables ----
fastboot getvar slot-count
fastboot getvar has-slot:boot
fastboot getvar all | grep slot

# ---- Unlock bootloader (wipes data!) ----
fastboot flashing unlock

  8. 8. Best practices

    • ✅ Check current-slot before any flash — you may be flashing to the wrong slot.
    • ✅ Flash both A and B slots when doing major updates — prevents slot-switch bootloops.
    • ✅ Try A/B switch first when recovering from a bootloop — it's non-destructive.
    • ✅ Keep the bootloader unlocked if you plan to use fastboot regularly.
    • ✅ After A/B switch, if the alternate slot boots, re-flash the corrupt slot with correct firmware.
    • ✅ Match firmware to the exact build — mismatched slot images cause baseband/touch failures.
    • ✅ Back up data before any unlock — unlocking wipes userdata.

Tip: A/B switching is the fastest, safest way to recover a bootloop that started after an OTA update. Try it first — before wiping data or flashing anything.
