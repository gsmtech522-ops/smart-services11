Fastbootd Mode vs Standard Fastboot Mode

Type
Technical Comparison
Level
Intermediate
Read Time
~10 minutes
Applies to
Android 10+ devices with dynamic partitions

Starting with Android 10, Google introduced Dynamic Partitions and split Fastboot into two distinct modes: Standard Fastboot (Bootloader level) and Fastbootd (Userspace level). Understanding the difference is essential when servicing modern devices, flashing GSI, or modifying dynamic partitions.

Reference

  1. 1. Standard Fastboot Mode

    Implemented inside the device's bootloader firmware (Boot ROM / LK). Runs at the lowest hardware level before any OS or recovery kernel loads.

    • Execution level: Hardware / Bootloader stage
    • Responsibilities: Unlock bootloaders, flash baseband/radio, boot temporary recovery/boot images, switch A/B slots, modify core static partitions (boot, dtbo, recovery, vbmeta)
    • Limitation: cannot read or modify dynamic logical partitions inside super

  2. 2. Fastbootd Mode

    A userspace Fastboot daemon running inside the Android recovery environment (Linux kernel level). Created specifically for dynamic partitions.

    • Execution level: Userspace / Recovery Kernel stage
    • Responsibilities: Resize, create, delete and flash logical partitions (system, vendor, product, system_ext, odm) inside super.img
    • Appearance: On-screen menu titled "fastbootd" with reboot options

  3. 3. Side-by-side comparison

    FeatureStandard FastbootFastbootd
    LevelBootloader (low-level)Userspace / recovery kernel
    IntroducedEarly Android releasesAndroid 10 (dynamic partitions)
    Entry commandadb reboot bootloaderadb reboot fastboot
    Core target filesboot.img, vbmeta.img, recovery.imgsystem.img, vendor.img, product.img
    Super partition accessFlashes super.img as wholeResizes & flashes sub-partitions inside super
    Bootloader unlock/lockSupportedNot supported

  4. 4. How to enter Fastbootd

    From active Android OS (ADB):

    adb reboot fastboot

    From Standard Fastboot Mode:

    fastboot reboot fastboot

    From Recovery: boot into recovery, navigate to Enter Fastboot or Reboot to Fastboot.

  5. 5. Troubleshooting

    Error: Flashing is not allowed in Bootloader mode / partition table doesn't exist

    Cause: trying to flash a dynamic partition (system.img, vendor.img) from standard Fastboot on Android 10+.

    Fix:

    fastboot reboot fastboot
fastboot flash system system.img

    Error: Not enough space to resize partition

    Cause: the GSI or system image is larger than the logical space inside super.

    Fix:

    fastboot delete-logical-partition product_a

    Error: slot switching fails in Fastbootd

    Cause: some slot management commands must run at the bootloader level.

    Fix:

    fastboot reboot bootloader
fastboot set_active a

  6. 6. Rule of thumb

    • Working with boot.img, Magisk root, vbmeta, or bootloader unlock → Standard Fastboot
    • Working with Custom ROMs, GSI, vendor.img, Android 10+ firmware dumps → Fastbootd
