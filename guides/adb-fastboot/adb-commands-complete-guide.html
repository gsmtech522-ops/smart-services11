ADB Commands Complete Guide — Hardware, Communication & Software Testing

Safety note: only run these commands on phones you own or are authorized to test. Several commands change settings, and some (pm clear, fastboot, uninstall) delete data permanently.

ADB (Android Debug Bridge) is a command-line tool from Google's Platform-Tools that lets a computer control and inspect an Android phone over USB or Wi-Fi. This guide covers setup, the complete host-side command list, and the most useful shell tools for hardware, communication, and software testing.

Reference

  1. 1. Setup

    1. Download Platform-Tools from developer.android.com for Windows, macOS, or Linux and unzip it.
    2. On the phone: Settings → About phone → tap Build number 7 times to unlock Developer options.
    3. Open Developer options and enable USB debugging.
    4. Connect the phone via USB and accept the "Allow USB debugging?" prompt.
    5. Run adb devices — the phone should appear with state device.

    Wireless debugging (Android 11+):

    adb pair :     # enter the 6-digit code shown on the phone
adb connect :          # port from the Wireless debugging screen
adb disconnect :

    Older phones (Android 10 and older):

    # Connect by USB once, then:
adb tcpip 5555
adb connect :5555

    Command shape: adb [-d | -e | -s <serial>] <command>

    • -s <serial> — target a specific device when multiple are attached
    • -d — target the only USB device
    • -e — target the only emulator

    adb shell <cmd> runs a command on the phone itself.

    Common tools inside adb shell:

    ToolUsed for
    pmPackage manager: list, enable, disable, grant permissions
    amActivity manager: start apps, send broadcasts, force-stop
    dumpsysStatus dump of any system service (battery, wifi, sensors)
    cmdCalls system services directly (e.g. cmd wifi, cmd package)
    settingsReads and writes system, secure and global settings
    inputFakes taps, swipes, key presses and text
    svcToggles Wi-Fi, mobile data, power stay-on, NFC
    getprop / setpropReads and writes system properties
    wmScreen size and density
    screencap / screenrecordScreenshots and video
    monkeyRandom UI stress events
    contentQueries content providers (contacts, SMS, settings)
    logcatSystem and app logs
    top, ps, df, freeCPU, processes, storage, memory
    getevent / sendeventRaw touch and button events
    telecom, locksettings, bmgr, appopsCalls, lock screen, backup, app operation permissions

  3. 3. Connection and device information

    CommandWhat it does
    adb devices -lLists connected devices with model and transport
    adb get-statePrints device, offline, or unauthorized
    adb get-serialnoPrints the device serial number
    adb wait-for-deviceBlocks until the phone is ready (useful in scripts)
    adb kill-server then adb start-serverRestarts the ADB daemon when stuck
    adb rebootReboots the phone
    adb reboot bootloaderReboots into bootloader (fastboot)
    adb reboot recoveryReboots into recovery
    adb shell getprop ro.product.modelModel name
    adb shell getprop ro.product.manufacturerManufacturer
    adb shell getprop ro.build.version.releaseAndroid version
    adb shell getprop ro.build.version.sdkAPI level
    adb shell getprop ro.build.fingerprintFull build fingerprint
    adb shell getprop ro.product.cpu.abiCPU architecture
    adb shell getpropEvery system property
    adb shell wm size / wm densityScreen resolution and DPI
    adb shell cat /proc/cpuinfoCPU details
    adb shell cat /proc/meminfoRAM details
    adb shell settings get secure android_idAndroid ID

    Android 10+: serial, IMEI and similar identifiers may be blocked for non-system apps. The old adb shell service call iphonesubinfo trick often returns nothing now.

  4. 4. Phone hardware tests

    All commands run through adb shell unless shown with the adb prefix. Some depend on Android version or manufacturer; a few need root.

    Battery and power:

    CommandUse
    dumpsys batteryLevel, status, temperature (tenths of °C), voltage, charger type
    dumpsys battery set level 15Fake a battery level to test low-battery behaviour
    dumpsys battery set ac 0 / set usb 0Fake an unplugged charger
    dumpsys battery resetUndo all fake values (always run after testing)
    dumpsys batterystatsDetailed drain by app since last charged
    dumpsys powerWake locks, screen state, sleep reasons

    Display and touch:

    CommandUse
    wm size / wm size 720x1280 / wm size resetRead, change, restore resolution
    wm density 320 / wm density resetChange or restore DPI
    settings put system screen_brightness 200Set brightness (0 to 255)
    settings put system screen_off_timeout 600000Screen timeout in milliseconds
    settings put system show_touches 1Show a dot at each touch
    settings put system pointer_location 1Overlay with live touch coordinates and trails
    getevent -ltRaw touchscreen and button events with timestamps
    input tap 540 1200Tap a point
    input swipe 300 1000 300 400 300Swipe over 300 ms
    dumpsys displayPanel size, refresh rate, HDR, brightness state

    Buttons: test via getevent -l — each physical button press should print a key event.

    # Keyevent codes for testing:
input keyevent 3    # Home
input keyevent 4    # Back
input keyevent 24   # Volume up
input keyevent 25   # Volume down
input keyevent 26   # Power
input keyevent 187  # Recents
input keyevent 82   # Menu

    Sensors: ADB cannot trigger a sensor on its own. Rotate or cover the phone and re-run the dump to confirm readings change. Dialer codes like *#0*# (Samsung) or *#*#4636#*#* open built-in hardware test menus on many phones.

    Camera, audio, vibration:

    CommandUse
    am start -a android.media.action.IMAGE_CAPTUREOpen the camera in photo mode
    am start -a android.media.action.VIDEO_CAPTUREOpen video mode
    dumpsys media.cameraCamera devices, supported modes, active clients
    dumpsys audioAudio routing, volumes, mute state, active players
    cmd media_session volume --stream 3 --set 10Set media volume (Android 11+)
    am start -a android.intent.action.VIEW -d file:///sdcard/test.mp3 -t audio/mpegPlay a file to test the speaker
    cmd vibrator_manager helpShows vibration test syntax (Android 12+)

    Location (GPS):

    CommandUse
    cmd location set-location-enabled trueTurn location on
    dumpsys locationProviders, last known fix, satellites, active requests

    Storage, memory, CPU, heat:

    CommandUse
    df -hPartition usage
    du -sh /sdcard/*Size of folders in shared storage
    dumpsys diskstatsApp, data and cache totals
    dumpsys meminfoMemory by process; add a package name for one app
    top -n 1One snapshot of CPU use
    dumpsys cpuinfoCPU use over recent minutes
    dumpsys thermalserviceTemperatures and throttling status
    cat /sys/class/thermal/thermal_zone0/tempRaw temperature reading (may be blocked)
    dumpsys usbUSB port mode and connection state
    dumpsys fingerprintFingerprint sensor state and enrolled count

  5. 5. Phone communication tests

    Commands below run inside adb shell unless they start with adb. Replace phone numbers with a number you control.

    Calls and SMS:

    CommandUse
    am start -a android.intent.action.DIAL -d tel:5551234567Opens the dialer with the number filled in
    am start -a android.intent.action.CALL -d tel:5551234567Places the call directly
    input keyevent 5Answers a ringing call
    input keyevent 6Ends a call
    dumpsys telephony.registryCall state, signal strength, network type, cell info
    dumpsys telecomActive and recent calls, audio route
    am start -a android.intent.action.SENDTO -d sms:5551234567 -es sms_body "Test message"Opens messaging app with a draft
    content query -uri content://sms/inboxReads received SMS (often blocked on newer Android)

    SIM and mobile network:

    CommandUse
    getprop gsm.sim.stateREADY when SIM works, ABSENT if none
    getprop gsm.operator.alphaCarrier name
    getprop gsm.network.typeNetwork type such as LTE or NR
    svc data disable / svc data enableMobile data off or on
    cmd connectivity airplane-mode enable / disableAirplane mode (Android 11+)
    dumpsys connectivityActive networks, validation state, DNS
    dumpsys netstatsData usage by network and app

    Wi-Fi:

    CommandUse
    svc wifi enable / svc wifi disableWi-Fi on or off
    cmd wifi statusConnection state, SSID, signal, link speed
    cmd wifi list-scan-resultsNearby networks and signal levels
    cmd wifi connect-network <SSID> wpa2 <password>Joins a network (Android 11+)
    dumpsys wifiFull Wi-Fi state, scan history, connection log
    ip addr show wlan0The phone's Wi-Fi IP address
    ping -c 4 8.8.8.8Tests internet reachability
    ping -c 4 google.comTests DNS as well
    ip routeRouting table and gateway

    Bluetooth and NFC:

    CommandUse
    svc bluetooth enable / disableBluetooth on or off
    dumpsys bluetooth_managerAdapter state, bonded devices, active profiles
    svc nfc enable / disableNFC on or off
    dumpsys nfcNFC state and last tag events

    Network behaviour testing:

    CommandUse
    settings put global http_proxy 192.168.1.10:8888Route traffic through a proxy
    settings put global http_proxy :0Remove the proxy
    adb forward tcp:8000 tcp:9000Computer port 8000 reaches phone port 9000
    adb reverse tcp:8081 tcp:8081Phone reaches a server on the computer
    adb forward --list / adb reverse --listShow active tunnels
    adb forward --remove-allClear forwards

  6. 6. Software tests

    Install and remove apps:

    CommandUse
    adb install app.apkInstalls an APK
    adb install -r app.apkReinstalls and keeps data
    adb install -d app.apkAllows a version downgrade
    adb install -g app.apkGrants all runtime permissions on install
    adb install-multiple base.apk split1.apkInstalls split APKs
    adb uninstall com.example.appRemoves the app
    adb uninstall -k com.example.appRemoves the app but keeps data

    Package manager (pm):

    CommandUse
    pm list packagesAll packages; add -3 user, -s system, -d disabled
    pm list packages | grep cameraFind a package by name
    pm path com.example.appLocation of the APK on the phone
    pm clear com.example.appWipes the app's data and cache
    pm disable-user --user 0 com.example.appDisables an app without root
    pm enable com.example.appRe-enables it
    pm grant com.example.app android.permission.CAMERAGrants a permission
    pm revoke com.example.app android.permission.CAMERARevokes it
    dumpsys package com.example.appVersion, permissions, install time, components

    Activity manager (am):

    CommandUse
    am start -n com.example.app/.MainActivityOpens a specific screen
    am start -W -n com.example.app/.MainActivityOpens it and prints launch time in ms
    am start -a android.intent.action.VIEW -d https://example.comTests a deep link or URL
    am force-stop com.example.appKills the app
    am kill com.example.appKills background processes only
    am broadcast -a android.intent.action.BOOT_COMPLETEDSends a broadcast
    am instrument -w com.example.app.test/androidx.test.runner.AndroidJUnitRunnerRuns instrumented tests
    monkey -p com.example.app 500Sends 500 random taps and gestures
    monkey -p com.example.app -s 42 --throttle 200 -v 1000Repeatable run (seed 42), 200ms between events

    Logs and crash analysis:

    CommandUse
    adb logcatLive system log
    adb logcat -cClears the log buffer
    adb logcat -d > log.txtSaves the current log and exits
    adb logcat *:EErrors only (levels: V, D, I, W, E, F)
    adb logcat -s MyTagOnly one tag
    adb logcat --pid=$(adb shell pidof -s com.example.app)One app's logs
    adb logcat -b crashCrash buffer
    adb bugreport report.zipFull diagnostic bundle: logs, dumpsys, ANRs, battery stats
    dumpsys activity processesRunning processes and their state
    dumpsys activity activitiesActivity stack and what is on screen now
    dumpsys window | grep mCurrentFocusThe app currently in the foreground

    Performance and system behaviour:

    CommandUse
    dumpsys gfxinfo com.example.appFrame times and jank percentage
    dumpsys gfxinfo com.example.app resetResets the frame counters before a test
    dumpsys meminfo com.example.appApp memory use and leak hints
    dumpsys deviceidle force-idleForces Doze to test background work
    dumpsys deviceidle unforceLeaves Doze
    am set-standby-bucket com.example.app rareTests app under restricted background limits
    cmd appops set com.example.app RUN_IN_BACKGROUND denyBlocks background running
    settings put global window_animation_scale 0Turns off animations for UI tests
    cmd uimode night yes / noDark mode on or off
    cmd locale set-app-locales com.example.app --locales frChanges app language (Android 13+)

    OS and update checks: getprop ro.build.version.security_patch (security patch date), getprop ro.build.version.incremental (build number), adb sideload update.zip (in recovery mode).

  7. 7. Files, screen, input, and other tools

    Files:

    CommandUse
    adb push local.txt /sdcard/Download/Computer to phone
    adb pull /sdcard/DCIM/Camera/ ./photosPhone to computer
    adb shell ls -l /sdcard/Lists files
    adb shell rm /sdcard/Download/old.txtDeletes a file
    adb shell mkdir /sdcard/testCreates a folder
    adb shell cat /sdcard/file.txtPrints a file

    Screenshots and screen recording:

    CommandUse
    adb exec-out screencap -p > shot.pngScreenshot straight to the computer
    adb shell screencap -p /sdcard/shot.pngScreenshot saved on the phone
    adb shell screenrecord /sdcard/demo.mp4Records video; stops after 180s or Ctrl+C
    adb shell screenrecord --time-limit 30 --size 1280x720 /sdcard/demo.mp4Shorter, smaller recording

    Input and automation:

    CommandUse
    input text "hello"Types text (use %s for spaces)
    input keyevent KEYCODE_HOMEPresses a key by name
    input tap x yTap
    input swipe x1 y1 x2 y2 [ms]Swipe; same start+end with long duration = long press
    input roll dx dyTrackball movement
    uiautomator dump /sdcard/ui.xmlSaves the screen's UI tree, useful for finding tap coordinates

    Settings — namespaces are system, secure, global:

    CommandUse
    settings list globalEvery global setting
    settings put global stay_on_while_plugged_in 3Keeps the screen on while charging
    settings put system accelerometer_rotation 0Locks auto-rotate off
    settings put global development_settings_enabled 1Developer options on

    Power, lock screen, and device state:

    CommandUse
    input keyevent 26Toggles screen on and off
    input keyevent 82Wakes or unlocks on phones without a PIN
    locksettings clear --old 1234Removes the lock PIN (Android 8+; needs old PIN)
    dumpsys window | grep -i keyguardChecks whether the lock screen is showing
    adb rebootRestart
    adb shell reboot -pPower off (may need root)

    Fastboot and recovery (separate from adb; bootloader mode):

    CommandUse
    fastboot devicesLists phones in fastboot mode
    fastboot getvar allPrints bootloader variables, including lock state
    fastboot flash boot boot.imgFlashes a partition
    fastboot oem unlock / fastboot flashing unlockUnlocks the bootloader; erases all data
    fastboot rebootReboots to Android
    adb reboot recoveryBoots recovery (for sideloading updates or factory reset)

    Backup and root: adb backup and adb restore are deprecated and fail for most modern apps. adb root, adb remount, and adb disable-verity only work on userdebug or engineering builds — not on normal retail phones.

  8. 8. Troubleshooting and quick checklist

    ProblemFix
    adb devices shows nothingTry another cable (some are charge-only) and USB port; set USB mode to File transfer; install the phone maker's USB driver on Windows
    State is unauthorizedUnlock the phone and accept the prompt; or revoke USB debugging authorizations in Developer options and reconnect
    State is offlineRun adb kill-server, then adb start-server; replug the cable
    More than one device/emulatorAdd -s <serial> from adb devices
    Command not found on a shell toolThe tool is missing on that Android version; check adb shell cmd -l
    Permission denied or SecurityExceptionThe command needs root, a system app, or a newer Android shell; check the version
    Wireless connection dropsKeep the phone and computer on the same network and re-run adb connect
    Fake battery values stuckRun adb shell dumpsys battery reset
    Changed screen size looks wrongRun adb shell wm size reset and adb shell wm density reset

    Ten-minute phone health check:

    1. adb devices -l to confirm the connection.
    2. getprop ro.build.version.release and dumpsys battery for OS version and battery health.
    3. df -h and dumpsys meminfo for storage and memory.
    4. settings put system pointer_location 1 then swipe over the screen to find dead touch zones; turn it off with 0.
    5. dumpsys sensorservice to confirm every expected sensor is listed.
    6. getprop gsm.sim.state and dumpsys telephony.registry for SIM and signal.
    7. cmd wifi status and ping -c 4 8.8.8.8 for Wi-Fi and internet.
    8. Open the camera with the IMAGE_CAPTURE intent and take a test photo.
    9. Play a sound, then record and play back a clip to check speaker and mic.
    10. adb bugreport report.zip to save a full report of the results.

Tip: bookmark this page and use Ctrl+F to search any command. Run adb help on your machine to see the exact list for your Platform-Tools version — the command count shifts slightly between releases.
