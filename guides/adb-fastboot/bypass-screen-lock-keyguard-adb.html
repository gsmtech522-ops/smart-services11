Bypass Screen Lock / Keyguard via ADB

Type
Advanced Guide
Level
Advanced
Time
~10 minutes
Applies to
Unlocked-bootloader devices (own device only)
Last updated
YYYY-MM-DD

Legal warning: this guide is ONLY for your own device or a device you are explicitly authorized to service (e.g. a customer’s device with written consent). Bypassing the screen lock on someone else’s phone without permission is illegal in most countries and can be traced back to you.

Encryption warning (Android 10+): modern devices use File-Based Encryption (FBE). User data is locked behind hardware-backed keymaster keys tied to the user PIN. Deleting locksettings.db on encrypted stock ROMs unbinds keymaster keys and renders user data permanently inaccessible until a factory reset. Only use Method 1 in a custom recovery on unencrypted/legacy devices — otherwise your data is lost, not recovered.

When servicing devices with forgotten PINs, patterns, or damaged touch digitizers where data retention is essential, standard factory resets are not an option. On devices with an unlocked bootloader, technicians can leverage ADB elevated privileges (or TWRP/custom recovery terminal access) to remove or bypass keyguard database files, force-disable the screen lock overlay, or temporarily inject input events.

Reference

  1. 1. Prerequisites

    • An Android device with an unlocked bootloader.
    • ADB & Fastboot installed on the PC.
    • Root access via ADB shell, or a custom recovery (TWRP/OrangeFox) with ADB enabled.
    • USB Debugging active, or recovery mode connected via USB.
    • Full data backup — if methods below go wrong on encrypted devices, you lose data.

  2. 2. Method 1 — Remove keyguard files via ADB / TWRP terminal

    The classic technique: delete the lock state database files directly without wiping user data. Only works reliably on legacy / unencrypted storage, or inside a custom recovery.

    1. Boot the device into TWRP/OrangeFox recovery, or boot into Android with rooted ADB active.
    2. Open Command Prompt and start the shell:
    adb shell
    1. If in booted Android, request root:
    su
    1. Remove all lock-related database and key files:
    rm -f /data/system/gatekeeper.password.key
rm -f /data/system/gatekeeper.pattern.key
rm -f /data/system/locksettings.db
rm -f /data/system/locksettings.db-wal
rm -f /data/system/locksettings.db-shm
rm -f /data/system/gesture.key
rm -f /data/system/password.key
    1. Reboot normally:
    reboot
    1. When the system loads, swipe up — any pattern or PIN prompt should be bypassed.

    FBE caveat: if the device is encrypted (Android 10+), this method will likely cause a bootloop or leave the data partition encrypted with lost keys. Read the encryption warning above before proceeding.

  3. 3. Method 2 — Disable lockscreen via settings injection (Android 8–11)

    If lock database files regenerate because of hardware keystore enforcement, force the lock setting values directly.

    1. Open ADB shell as root:
    adb shell
su
    1. Disable keyguard lock flags:
    locksettings set-disabled true
    1. Clear the existing PIN/password if you know the old value:
    locksettings clear --old 0000

    If the old PIN is unknown, set-disabled true can force the keyguard overlay to stop showing — but does not decrypt the device.

  4. 4. Method 3 — Unlock via ADB input events (broken touch screen)

    If you know the PIN/pattern but the digitizer is cracked and unresponsive, emulate touch input via ADB.

    1. Wake the screen:

    adb shell input keyevent 26

    2. Swipe up to reveal PIN entry:

    adb shell input swipe 300 1000 300 300

    3. Type the PIN (example: 1234) and press Enter:

    adb shell input text 1234
adb shell input keyevent 66

    Keyevent 66 = Enter. Once unlocked, immediately pull your data:

    adb pull /sdcard/ D:\backup\

    Coordinates are device-specific: the swipe 300 1000 300 300 works on 1080×2400 screens. For other resolutions, adjust proportionally. Use adb shell wm size to check.

  5. 5. Method 4 — Direct property override (custom ROMs only)

    For custom development ROMs or test builds, keyguard can be suppressed without modifying on-disk files:

    adb shell su -c "setprop keystore.no_matching_objects true"
adb shell su -c "wm dismiss-keyguard"

    This only works on ROMs that allow this property — it will not work on stock firmware with hardware keymaster.

  6. 6. Crucial security & compatibility notes

    File-Based Encryption (FBE) on Android 10+

    Modern devices use File-Based Encryption (FBE) and hardware-backed keymaster. User data is not just protected by a database file — it is cryptographically locked behind a key derived from the PIN. Deleting locksettings.db on modern encrypted stock ROMs will:

    • Unbind the keymaster keys tied to the PIN
    • Make the user data partition unreadable
    • Force a full factory reset to make the device usable

    Bottom line: Method 1 only works reliably on legacy devices or in custom recovery before data is encrypted. On modern stock encrypted devices, no data-retaining lock bypass exists — this is by design.

    Immediate action after successful bypass

    • Open Settings → Developer Options to verify ADB backup still works.
    • Run adb pull /sdcard/ to pull user files.
    • Change the PIN immediately or re-enable lock with a known value.
    • Document the operation for any customer-device service record.

  7. 7. Troubleshooting

    ProblemFix
    rm command returns "Operation not permitted"Not rooted, or ADB shell is not root. Run su first.
    Lock files reappear immediatelyKeystore regenerated them. Use locksettings set-disabled true (Method 2) instead.
    Bootloop after deleting locksettings.dbEncrypted device — data partition lost keys. Full factory reset required.
    locksettings command not foundAndroid 8+ required. On older Android, only Method 1 works.
    ADB unauthorizedEnable USB Debugging. On locked screen you may need adb shell input keyevent 26 to wake first.
    Touch screen broken, swipe missUse adb shell input tap X Y for digit button presses. Get coordinates from screen resolution via wm size.
    Customer phone — legal issueAlways get written authorization before attempting any lock bypass.

adb shell

# ---- Method 1: Remove keyguard lock files ----

rm -f /data/system/gatekeeper.pattern.key
rm -f /data/system/locksettings.db
rm -f /data/system/locksettings.db-wal

adb shell input keyevent 26              # wake
adb shell input swipe 300 1000 300 300   # swipe up
adb shell input text 1234                # type PIN
adb shell input keyevent 66              # press Enter

# ---- Verify resolution for accurate swipe ----
adb shell wm size
adb shell wm density

adb shell su -c "wm dismiss-keyguard"

# ---- After bypass — backup data ----
adb pull /sdcard/ D:\backup\

  9. 9. Best practices

    • ✅ Only bypass the lock on your own device or with written authorization.
    • ✅ Back up all data first via adb pull if the device allows it.
    • ✅ Confirm whether the device is encrypted before attempting Method 1.
    • ✅ Use custom recovery (TWRP) for Method 1 — safest place to modify system files.
    • ✅ Use Method 3 (input events) whenever the PIN is known but the screen is broken.
    • ✅ Change the PIN immediately after successful bypass.
    • ✅ Document every customer-device operation.

Tip: If the goal is only to recover data from a broken-screen device with a known PIN, Method 3 (input events) is by far the safest. It doesn’t modify any files and preserves encryption integrity. Always pull data to PC before returning the device.
