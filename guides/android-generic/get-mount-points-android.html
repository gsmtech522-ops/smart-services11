How to Get Mount Points & Partition Info on Android

Type
Reference Guide
Level
Intermediate
Time
~5 minutes
Applies to
All Android devices with ADB access
Last updated
YYYY-MM-DD

When you need to extract a partition, flash an image, or repair a mount issue, the first step is knowing which block device maps to which mount point. Android's storage layout is device-specific and has evolved heavily since Android 10 (dynamic partitions, device-mapper, per-process mounts). This guide shows every method to list mount points and partition mappings via ADB.

Reference

  1. 1. Quick method — df command

    The simplest way to see mounted filesystems and their block devices:

    adb shell df -h

    Output example:

    Filesystem       Size  Used Avail Use% Mounted on
/dev/block/dm-17 1.4G  1.4G     0 100% /
/dev/block/dm-18 4.1G  2.6G   1.4G  66% /data
/dev/block/sda14 100M   20M    80M  20% /vendor

    Note: df shows mounted filesystems. Some partitions (like boot, recovery, modem) are never mounted during normal Android operation, so they won't appear here [citation:3].

  2. 2. Detailed method — /proc/mounts

    Shows every mounted filesystem with full device path, mount point, filesystem type, and flags:

    adb shell cat /proc/mounts

    Filter to see only physical partitions:

    adb shell cat /proc/mounts | grep "/dev/block"

    Output example:

    /dev/block/dm-17 / ext4 ro,seclabel,relatime 0 0
/dev/block/dm-18 /data ext4 rw,seclabel,nosuid,nodev,noatime 0 0
/dev/block/mmcblk0p1 /vendor ext4 ro,seclabel,relatime 0 0

    Tip: /proc/self/mountinfo is newer and more complete than /proc/mounts — it includes mount IDs, parent IDs, and mount propagation info [citation:9].

  3. 3. All partitions (mounted + unmounted) — /proc/partitions

    Lists every block device the kernel knows about, even if not mounted:

    adb shell cat /proc/partitions

    Output example:

    major minor  #blocks  name
 179        0   61071360 mmcblk0
 179        1       8192 mmcblk0p1
 179        2      16384 mmcblk0p2
 179       21     524288 mmcblk0p21
 253        0    1048576 dm-0
 253        1    4194304 dm-1

    This is essential when you need to find a partition that isn't currently mounted (e.g. boot, modemst1) [citation:3][citation:11].

  4. 4. Find partition-by-name symlinks

    Modern Android exposes partitions through by-name symlinks, so you don't need to know the raw mmcblk0p21 number:

    Step 1 — Locate the by-name directory (device-specific):

    adb shell find /dev -name "by-name" 2>/dev/null

    Typical outputs:

    • /dev/block/platform/soc/1d84000.ufshc/by-name (UFS devices)
    • /dev/block/platform/msm_sdcc.1/by-name (older Qualcomm eMMC)
    • /dev/block/by-name (symlink common on modern devices)

    Step 2 — List all partitions with their block device numbers:

    adb shell ls -al /dev/block/by-name/

    Output example:

    lrwxrwxrwx root root boot -> /dev/block/sda12
lrwxrwxrwx root root system -> /dev/block/sda13
lrwxrwxrwx root root vendor -> /dev/block/sda14
lrwxrwxrwx root root userdata -> /dev/block/sda15
lrwxrwxrwx root root modem -> /dev/block/sda16

    This is the safest way to flash or backup a partition without guessing [citation:8][citation:12].

  5. 5. Resolve dm-* (device-mapper) to real partitions

    On Android 10+ with dynamic partitions, many mounted filesystems show as /dev/block/dm-X — a device-mapper virtual node. To find which logical partition it represents:

    Method A — Check the dm name:

    adb shell cat /sys/block/dm-0/dm/name
adb shell cat /sys/block/dm-1/dm/name

    Output example:

    system
userdata

    This requires root or a userdebug/eng build [citation:14].

    Method B — Correlate with mount points:

    adb shell cat /proc/mounts | grep dm-

    Output shows which dm-X is mounted at /, /data, /vendor, etc. Combined with the by-name list (which shows the raw super partition), you can infer the mapping.

    Why dm-X? On dynamic partitions, system, vendor, product are logical sub-partitions inside the physical super partition. The kernel maps each one through device-mapper [citation:14].

  6. 6. Root-only — full mount command output

    If you have root, the mount command shows everything with full flags:

    adb shell su -c mount

    Filter to a specific partition:

    adb shell su -c "mount | grep system"

    Output example:

    /dev/block/dm-17 on /system type ext4 (ro,seclabel,relatime)

    Note: without root, the mount command may still work but shows limited info. /proc/mounts is more reliable for non-root users [citation:5].

  7. 7. Common partitions you should know

    Partition nameUsually mounted atPurpose
    system / dm-0/ or /systemAndroid framework
    vendor/vendorHAL drivers
    userdata / dm-1/dataUser apps and files
    bootNot mountedKernel + ramdisk
    recoveryNot mountedRecovery mode
    modemNot mountedBaseband firmware
    persistNot mountedSensor calibration
    superNot mountedDynamic partitions container

  8. 8. Per-process mount isolation (Android 10+)

    Android leverages Linux per-process mount namespaces. A process launched from adbd may see different mounts than an app process launched by zygote [citation:3][citation:7].

    To inspect an app's view of mounts, use:

    adb shell cat /proc/self/mounts

    This shows the mounts visible to your current ADB shell session, which is usually the "base" view.

  9. 9. Complete command reference

    # ---- Quick overview of mounted filesystems ----
adb shell df -h
adb shell df -h /

# ---- Full mount table ----
adb shell cat /proc/mounts
adb shell cat /proc/mounts | grep "/dev/block"

# ---- Mount info (newer, more detailed) ----
adb shell cat /proc/self/mountinfo

# ---- All known partitions (mounted + unmounted) ----
adb shell cat /proc/partitions

# ---- Locate by-name symlinks ----
adb shell find /dev -name "by-name" 2>/dev/null

# ---- List partitions with block device mapping ----
adb shell ls -al /dev/block/by-name/

# ---- Resolve dm-X (root/userdebug only) ----
adb shell cat /sys/block/dm-0/dm/name
adb shell cat /sys/block/dm-1/dm/name

# ---- Root-only full mount output ----
adb shell su -c mount
adb shell su -c "mount | grep system"

# ---- Check SELinux context on a mount ----
adb shell ls -Z /system

  10. 10. Troubleshooting

    ProblemFix
    find /dev -name by-name returns nothingTry ls /dev/block/by-name/ directly — the symlink may exist without the directory being findable [citation:8].
    /proc/partitions shows nothing usefulNon-root may see limited info on some builds. Try ls /dev/block/ instead.
    dm-X name is blankRequires root or a userdebug build. Use /proc/mounts correlation instead.
    Partition not listed anywhereIt may not be mapped in by-name on your device. Use /proc/partitions and match by size.
    df shows 100% on /Normal on dynamic partitions — the logical size is fixed. Check /data for real free space.
    Cannot read /proc/mountsSome OEM ROMs restrict it. Root solves this.

  11. 11. Best practices

    • ✅ Prefer by-name symlinks over raw block numbers — they are stable and readable.
    • ✅ Use /proc/partitions to find unmounted partitions (boot, modem).
    • ✅ Remember that dm-X is a virtual layer over super on Android 10+.
    • ✅ Always double-check the block device before flashing — wrong device = brick.
    • ✅ Back up nvram / modemst1 before any partition operation.
    • ✅ Use df -h for a quick sanity check before deep diagnostics.

Tip: if you're writing an extraction script, start with adb shell ls /dev/block/by-name/ — it gives you every partition name and its exact block device in one command, no root required on most devices.
