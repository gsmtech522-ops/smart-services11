How to Mount & Extract ext4 Android Images on Windows

Type
Step-by-Step Guide
Level
Intermediate
Time
~10 minutes
Applies to
Windows 10/11 — system.img, vendor.img, userdata.img, super.img
Last updated
YYYY-MM-DD

Windows cannot natively mount Linux ext4 filesystems, so Android partition images like system.img, vendor.img and userdata.img cannot be opened with a double-click. Fortunately, several tools let you read (and in some cases write) ext4 images on Windows. This guide covers all working methods, from the simplest read-only extraction to full read-write mounting.

Reference

  1. 1. First — check if the image is actually ext4

    Many Android images are sparse (magic 3A FF 26 ED), not raw ext4. Windows tools will fail on sparse images. Convert first.

    Check file type in PowerShell:

    $bytes = [System.IO.File]::ReadAllBytes("C:\firmware\system.img")[0..3]
[System.BitConverter]::ToString($bytes)
    • 3A-FF-26-ED → sparse. Convert with simg2img first .[citation:1][citation:4]
    • 53-EF at offset 1080 → raw ext4. Ready to mount.

    Convert sparse to raw (WSL or simg2img.exe):

    simg2img system.img system_raw.img

    Why convert? A sparse image is a container format — tools like 7-Zip and LinuxReader cannot parse the ext4 filesystem inside until it is converted to raw .[citation:1]

  2. 2. Method 1 — 7-Zip (easiest, read-only, no install)

    7-Zip has built-in read-only support for ext2/ext3/ext4. It parses the filesystem directly without mounting — perfect for quick file extraction .[citation:3]

    1. Install 7-Zip (latest version).
    2. Right-click your system_raw.img → 7-Zip → Open archive.
    3. Browse the filesystem tree inside the image.
    4. To extract files: select them → right-click → Extract to…

    Read-only: 7-Zip cannot write back into the image. If you need to modify files, use WSL2 or Pengwin .[citation:3]

  3. 3. Method 2 — WSL2 (read-write, recommended)

    WSL2 runs a real Linux kernel, so you can mount ext4 images properly and modify them. Best for technicians who need to edit system.img .[citation:8][citation:12]

    Step 1 — Install WSL2 (once):

    wsl --install -d Ubuntu

    Reboot, complete Ubuntu setup.

    Step 2 — Copy image into WSL home:

    cp /mnt/c/firmware/system_raw.img ~/system_raw.img

    Important: do not loop-mount directly from /mnt/c/. Copy the image to the WSL filesystem first — mounting over the Windows bridge is unreliable .[citation:8]

    Step 3 — Mount and edit:

    sudo mkdir -p /mnt/system
sudo mount -o loop,rw ~/system_raw.img /mnt/system
ls /mnt/system

    Step 4 — Modify files, then unmount:

    sudo cp ~/MyApp.apk /mnt/system/system/app/MyApp/
sudo umount /mnt/system
sudo e2fsck -f -y ~/system_raw.img

    Step 5 — Access from Windows (read-only through WSL):

    Open File Explorer and navigate to:

    \\wsl$\Ubuntu\mnt\system

  4. 4. Method 3 — LinuxReader (read-only, GUI)

    DiskInternals LinuxReader is a free Windows app that reads ext2/ext3/ext4 images without installing a filesystem driver .[citation:6][citation:11]

    1. Download and install LinuxReader from diskinternals.com.
    2. Launch the app.
    3. Click Drives → Mount Image.
    4. Browse to your system_raw.img → Open.
    5. Browse the filesystem tree.
    6. To extract a file: right-click → Save → choose destination.

    LinuxReader also opens sparse images directly? No — convert with simg2img first. LinuxReader only handles raw ext4 .[citation:11]

  5. 5. Method 4 — Pengwin (native drive letter, read-write)

    Pengwin is a Rust-based ext4 driver that mounts images as a real Windows drive letter using WinFsp. It is read-only by default, and read-write with the --rw flag .[citation:7]

    Step 1 — Install WinFsp:

    Download and run the WinFsp installer (Core component is enough).

    Step 2 — Download pengwin.exe:

    Place it anywhere on your PATH.

    Step 3 — Mount the image:

    pengwin mount C:\firmware\system_raw.img Z:

    The image appears as drive Z: in File Explorer.

    Step 4 — Read-write mode (optional):

    pengwin mount --rw C:\firmware\system_raw.img Z:

    Step 5 — Unmount when done:

    pengwin unmount Z:

    Use case: Pengwin is ideal when you need a native drive letter but cannot use WSL (e.g. the ext4 partition is on the same physical disk as Windows, which WSL refuses to mount) .[citation:7]

  6. 6. Quick comparison

    ToolReadWriteDrive letterSetup

    Ext2Fsd warning: it installs a kernel driver and has caused data corruption on ext4 volumes. Avoid it unless you accept the risk .[citation:6]

  7. 7. Handling super.img (dynamic partitions)

    On Android 10+, system.img and vendor.img may be inside super.img as logical partitions. You cannot mount super.img directly as ext4.

    1. Convert sparse super to raw:
    simg2img super.img super_raw.img
    1. Extract logical partitions with lpunpack (WSL):
    lpunpack super_raw.img ./output/
    1. You now have system.img, vendor.img, product.img as separate raw ext4 images.
    2. Mount each with the methods above.

  8. 8. Troubleshooting

    ProblemFix
    7-Zip says "Cannot open file as archive"Image is sparse. Convert with simg2img first .[citation:1]
    WSL mount fails "wrong fs type"Image is sparse or EROFS. Convert to raw ext4.
    WSL mount fails "already mounted"Another WSL instance has it open. Run wsl --shutdown and retry.
    LinuxReader shows nothingImage is sparse or not ext4. Convert first.
    Pengwin mount fails "dirty journal"Filesystem was not cleanly unmounted. Use --rw to replay the journal .[citation:7]
    WSL cannot mount a partition on the same disk as WindowsWSL refuses. Use Pengwin instead .[citation:7]
    Files vanish after unmountYou may have mounted read-only (ro). Use -o loop,rw.

  9. 9. Complete command reference

    # ---- Convert sparse to raw ----
simg2img system.img system_raw.img

# ---- 7-Zip (read-only) ----
# Right-click system_raw.img → 7-Zip → Open archive

# ---- WSL2 (read-write) ----
cp /mnt/c/firmware/system_raw.img ~/system_raw.img
sudo mkdir -p /mnt/system
sudo mount -o loop,rw ~/system_raw.img /mnt/system
# edit files...
sudo umount /mnt/system
sudo e2fsck -f -y ~/system_raw.img
# Access from Windows: \\wsl$\Ubuntu\mnt\system

# ---- LinuxReader (read-only) ----
# Drives → Mount Image → select system_raw.img

# ---- Pengwin (read-write, drive letter) ----
pengwin mount C:\firmware\system_raw.img Z:
pengwin mount --rw C:\firmware\system_raw.img Z:
pengwin unmount Z:

# ---- Extract logical partitions from super.img ----
simg2img super.img super_raw.img
lpunpack super_raw.img ./output/

# ---- Shut down WSL if mount is stuck ----
wsl --shutdown

  10. 10. Best practices

    • ✅ Always check if the image is sparse before mounting.
    • ✅ Convert to raw ext4 with simg2img first .[citation:1]
    • ✅ Use 7-Zip for quick read-only extraction — no install needed.
    • ✅ Use WSL2 for read-write modifications .[citation:8]
    • ✅ Copy images into WSL home directory before mounting — do not mount from /mnt/c/.
    • ✅ Run e2fsck after every modification.
    • ✅ Use Pengwin if you need a real drive letter or cannot use WSL .[citation:7]
    • ✅ Avoid Ext2Fsd — it has corrupted ext4 volumes.

Tip: if you only need to pull a few files (e.g. an APK or config from system.img), 7-Zip is the fastest path. If you need to modify system.img and flash it back, use WSL2 — it is the most reliable read-write method on Windows.
