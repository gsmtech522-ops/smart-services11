How to Verify vbmeta Image Contents & AVB Signatures

Type
Reference Guide
Level
Advanced
Time
~10 minutes
Applies to
Android 8+ devices with AVB 2.0
Last updated
YYYY-MM-DD

Android's vbmeta.img is the central "root of trust" for Verified Boot. It contains the signatures and hash descriptors that the bootloader uses to verify every other partition (boot, system, vendor, etc.). If a single byte is modified in a partition without re-signing, the bootloader rejects it. This guide shows how to inspect a vbmeta image, verify its internal signature, and compare hash descriptors against actual partition images using avbtool and avbroot.

Reference

  1. 1. What's inside vbmeta.img?

    A vbmeta image has three main sections:

    SectionContent
    HeaderVersion, algorithm, flags, descriptor offsets
    Authentication DataRSA signature over the header + auxiliary data
    Auxiliary DataHash descriptors, hashtree descriptors, chained vbmeta descriptors

    Descriptors are the "contract" — they say "the boot partition must hash to X with salt Y" [citation:9].

  2. 2. Prerequisites

    • Python 3.5+
    • avbtool — from AOSP external/avb or bundled with Magisk
    • avbroot (optional) — for on-device verification [citation:8]
    • Your vbmeta.img extracted from firmware
    • The corresponding partition images (boot.img, system.img, etc.)

    Get avbtool:

    git clone https://android.googlesource.com/platform/external/avb
cd avb
python3 avbtool.py --help

  3. 3. Step 1 — Inspect the vbmeta image contents

    The info_image command dumps all metadata and descriptors without modifying anything [citation:7][citation:9]:

    python3 avbtool.py info_image --image vbmeta.img

    Output includes:

    Minimum libavb version:   1.0
Header Block:             256 bytes
Authentication Block:     576 bytes
Auxiliary Block:          3456 bytes
Algorithm:                SHA256_RSA4096
Rollback Index:           0
Flags:                    0
Release String:           'avbtool 1.1.0'
Descriptors:
    Hashtree descriptor:
      Version of dm-verity:  1
      Image Size:            1056714752 bytes
      Tree Offset:           1056714752
      Tree Size:             8327168 bytes
      Data Block Size:       4096 bytes
      Hash Block Size:       4096 bytes
      FEC num roots:         2
      Hash Algorithm:        sha256
      Partition Name:        system
      Salt:                  baa1ce5d7db69d1b3943a78b5b142ae4d77b4ed60b9885c8661e845172b29a13
      Root Digest:           ec7cb1ad89fed3104a03191434d5487b5b4acc78e6bfeb84d7178af40df7db75
      Flags:                 0
    Hash descriptor:
      Image Size:            35553280 bytes
      Hash Algorithm:        sha256
      Partition Name:        boot

      Digest:                2597c218aae470a130f61162feaae70afd97f011

    Key fields:

    • Algorithm: signature algorithm (e.g. SHA256_RSA4096)
    • Flags: bit 0 = HASHTREE_DISABLED, bit 1 = VERIFICATION_DISABLED [citation:9]
    • Descriptors: one entry per partition — lists partition name, salt, digest/root digest

  4. 4. Step 2 — Verify the vbmeta signature itself

    The verify_image command checks the internal signature against the embedded public key [citation:3]:

    python3 avbtool.py verify_image --image vbmeta.img

    Output on success:

    vbmeta: Successfully verified SHA256_RSA4096 hash of vbmeta.img

    If the output says "FAILED" or "signature verification failed", the vbmeta image has been tampered with or is corrupt.

    What this verifies: the signature covers the header + auxiliary data (descriptors). It does not verify the actual partitions — that is a separate step.

  5. 5. Step 3 — Verify a partition against its hash descriptor

    To check if a partition image (boot.img, system.img) matches what vbmeta expects, use verify_image with the --key flag pointing to the public key:

    Extract the public key from vbmeta first:

    python3 avbtool.py extract_public_key --key vbmeta.img --output public_key.bin

    Verify the partition:

    python3 avbtool.py verify_image --image boot.img --key public_key.bin

    On success:

    boot: Successfully verified SHA256_RSA4096 hash of boot.img

    If it fails, boot.img does not match the vbmeta descriptor — it has been modified or is a different build.

    Hashtree vs hash: boot.img uses a hash descriptor (simple SHA256). system.img uses a hashtree descriptor (dm-verity tree). The same verify_image command handles both, but the failure message differs.

  6. 6. Step 4 — Manual hash verification (educational)

    To understand how AVB hashing works, you can manually recompute the digest. AVB hashes salt ‖ first Image Size bytes of the partition — not the whole partition [citation:5].

    Example for boot.img:

    1. From info_image output, note:
      • Image Size (e.g. 35553280 bytes)
      • Salt (hex string)
      • Digest (expected hash)
    2. Convert salt hex to binary:
    python3 -c "import binascii; open('salt.bin','wb').write(binascii.unhexlify('YOUR_SALT_HEX'))"
    1. Compute hash over salt + first N bytes of the partition:
    cat salt.bin <(dd if=boot.img bs=1 count=35553280 2>/dev/null) | sha256sum
    1. Compare the result with the Digest value from info_image. If they match, the partition is intact [citation:5].

    Why this matters: understanding the salt + Image Size mechanic is essential for debugging why a partition "looks" correct but fails verification — usually because you hashed the entire partition instead of just the Image Size portion.

  7. 7. Step 5 — On-device verification with avbroot

    avbroot adds a powerful avb verify-device command that runs on the Android device itself and verifies all partitions against the live vbmeta [citation:8]:

    Requirements: rooted device, ADB shell access.

    # Push avbroot binary to device
adb push avbroot /data/local/tmp/
adb shell chmod +x /data/local/tmp/avbroot

# Run verification as root
adb shell su -c "/data/local/tmp/avbroot avb verify-device"

    Output shows each partition and whether it matches the vbmeta descriptor [citation:8]:

    INFO vbmeta has a signed vbmeta header
INFO Verifying hash descriptor for: boot
INFO Verifying hash descriptor for: vendor_boot
INFO Verifying hash tree descriptor for: system
INFO Verifying hash tree descriptor for: vendor
INFO Successfully verified all vbmeta signatures and hashes

    If any partition fails, avbroot reports it clearly — this is the fastest way to diagnose why a device boots with a "corrupt" warning.

  9. 9. Complete command reference

    # ---- Install avbtool ----
git clone https://android.googlesource.com/platform/external/avb
cd avb

# ---- Inspect vbmeta contents ----
python3 avbtool.py info_image --image vbmeta.img

# ---- Verify vbmeta signature ----
python3 avbtool.py verify_image --image vbmeta.img

# ---- Extract public key ----
python3 avbtool.py extract_public_key --key vbmeta.img --output public_key.bin

# ---- Verify a partition against vbmeta ----
python3 avbtool.py verify_image --image boot.img --key public_key.bin
python3 avbtool.py verify_image --image system.img --key public_key.bin

# ---- Manual hash verification ----
# 1. Get salt and image size from info_image
# 2. Convert salt hex to binary
python3 -c "import binascii; open('salt.bin','wb').write(binascii.unhexlify('SALT_HEX'))"
# 3. Hash salt + first N bytes
cat salt.bin <(dd if=boot.img bs=1 count=IMAGE_SIZE 2>/dev/null) | sha256sum

# ---- On-device verification (avbroot) ----
adb push avbroot /data/local/tmp/
adb shell chmod +x /data/local/tmp/avbroot
adb shell su -c "/data/local/tmp/avbroot avb verify-device"

# ---- Check AVB flags ----
python3 avbtool.py info_image --image vbmeta.img | grep -i flags

  10. 10. Best practices

    • ✅ Always verify vbmeta signature before relying on its descriptors.
    • ✅ Use verify_image instead of manual hashing when possible.
    • ✅ Extract the public key from the exact vbmeta you are checking against.
    • ✅ Remember: hash descriptors cover Image Size bytes, not the whole partition.
    • ✅ On-device avbroot verify-device is the fastest diagnostic for "corrupt" boot warnings.
    • ✅ Keep stock vbmeta images for each build — you need them to restore a device.
    • ✅ If a partition verify fails, the partition is modified — re-flash stock or re-sign.

Tip: if your device shows "Your device is corrupt" after flashing, run avbtool verify_image on each partition against the vbmeta public key. The failing partition tells you exactly what to re-flash or re-sign.
