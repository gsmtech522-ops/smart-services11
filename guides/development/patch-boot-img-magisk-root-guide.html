How to Patch boot.img with Magisk & Root Android

Type
Step-by-Step Guide
Level
Intermediate
Time
~15 minutes
Applies to
Most Android devices with unlocked bootloader
Last updated
YYYY-MM-DD

Critical warning: NEVER flash a patched image shared by someone else, or patch an image on a different device — even if it's the same model. Always patch the boot image on the same device where you want to install Magisk. Otherwise you may need a full data wipe to recover [citation:2].

Magisk works by patching the device's boot image (or init_boot/recovery depending on the device) and flashing it back. This guide walks through the official Magisk patch method — the safest and most reliable way to gain root on modern Android.

Reference

  1. 1. Which partition should you patch?

    Device eraPartition to patchNotes
    Android ≤ 12 (most devices)boot.imgStandard method
    Android 13+ GKI (Pixel 7+, many 2023+ devices)init_boot.imgIf init_boot.img exists in the factory image, patch it instead [citation:11]
    No ramdisk in boot (older system-as-root)recovery.imgRoot only active when booted to recovery [citation:2]

    How to check: in the Magisk app home screen, look at the Ramdisk value. Yes = patch boot.img. No = patch recovery.img [citation:2]. If you're on Android 13+ and the factory image contains init_boot.img, always patch that instead.

  2. 2. Prerequisites

    • Unlocked bootloader — mandatory for flashing boot images.
    • ADB & Fastboot installed on PC.
    • Magisk app installed on the device (latest version).
    • Stock boot/init_boot/recovery image matching your exact build number.
    • USB Debugging enabled.
    • Charged battery (50%+) and a quality USB cable.

    Firmware match: the boot image must match the exact build currently running on your device. A mismatched image causes Wi-Fi, Bluetooth, or touch failures. Check your build number in Settings → About phone and download the matching factory image [citation:11].

  3. 3. Step 1 — Get the stock boot image

    Extract the correct image from your device's full OTA or factory package:

    • Pixel / AOSP: extract from the factory image zip.
    • Xiaomi / OnePlus / Realme: extract from the full OTA zip or fastboot package.
    • If the image is sparse: convert with simg2img first.

    Transfer it to the device:

    adb push boot.img /sdcard/Download/

    For Android 13+ GKI devices, push init_boot.img instead:

    adb push init_boot.img /sdcard/Download/

  4. 4. Step 2 — Patch with Magisk

    1. Open the Magisk app on the device.
    2. In the Magisk card, tap Install.
    3. Select Select and Patch a File.
    4. Navigate to /sdcard/Download/ and select boot.img (or init_boot.img / recovery.img).
    5. If you are patching a recovery image, tick the Recovery Mode option [citation:2].
    6. Tap Let's Go and wait for the process to complete.
    7. Magisk outputs: magisk_patched-XXXXX_YYYYY.img in the same Download folder.

  5. 5. Step 3 — Pull the patched image to PC

    adb pull /sdcard/Download/magisk_patched-XXXXX_YYYYY.img .

    Note the exact filename — you will need it in the next step.

  6. 6. Step 4 — Test-boot before flashing (recommended)

    You can temporarily boot the patched image without writing it to storage — this verifies it works before making a permanent change [citation:5][citation:11].

    adb reboot bootloader
fastboot boot magisk_patched-XXXXX_YYYYY.img

    If the device boots and su works, the image is correct. If it boots but no root, you patched the wrong partition. If it does not boot, the image is not valid for this build [citation:5].

    OEM restriction: some manufacturers (notably Xiaomi) disable fastboot boot. If you see FAILED (remote: 'unknown command'), skip this step and flash directly [citation:5].

  7. 7. Step 5 — Flash the patched image

    Reboot into Fastboot if not already there, then flash the correct partition:

    For boot.img (Android 12 and older):

    fastboot flash boot magisk_patched-XXXXX_YYYYY.img

    For init_boot.img (Android 13+ GKI):

    fastboot flash init_boot magisk_patched-XXXXX_YYYYY.img

    For recovery.img (no-ramdisk devices):

    fastboot flash recovery magisk_patched-XXXXX_YYYYY.img

    For A/B slot devices, you can flash both slots to avoid slot-switch bootloops:

    fastboot flash boot_a magisk_patched-XXXXX_YYYYY.img
fastboot flash boot_b magisk_patched-XXXXX_YYYYY.img

  8. 8. Step 6 — Reboot and verify

    fastboot reboot

    After boot:

    1. Open the Magisk app. The Installed field should show a version number (not N/A).
    2. If Magisk asks for "Requires additional setup", tap it and let the device reboot.
    3. Verify root from PC:
    adb shell "su -c 'id'"

    You should see uid=0(root) in the output [citation:11].

  9. 9. Optional — Disable vbmeta verification

    If the device bootloops or shows "Your device is corrupt" after flashing, you may need to disable AVB/verity:

    fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img

    Data wipe warning: flashing vbmeta with these flags may wipe your data. Back up first. This is not universally required — only do it if the device fails to boot [citation:5].

  10. 10. Troubleshooting

    ProblemCauseFix
    FAILED (remote: 'Flashing is not allowed in Lock State')Bootloader still lockedUnlock bootloader first [citation:5]
    FAILED (remote: 'unknown command') on fastboot bootOEM disabled RAM bootSkip test-boot and flash directly [citation:5]
    Boots but Magisk says "Requires additional setup"Wrong partition patched, or app-only installRedo the patch with the correct partition [citation:5]
    Bootloop after flashingSlot mismatch, or userdata cannot decryptRe-flash stock image, boot, retry. On A/B devices flash both slots [citation:5]
    Device corrupt screenAVB rejected the patched imageFlash stock factory image, then disable verity/vbmeta [citation:5]
    Root works then stops after OTAOTA replaced the boot partitionRe-patch the new build's image [citation:5]
    getenforce shows PermissiveSomething ran setenforce 0Run su -c 'setenforce 1' and find the culprit [citation:5]

  11. 11. Complete command reference

    # ---- Check build and unlock state ----
adb shell getprop ro.build.fingerprint    # must match boot image
adb shell getprop ro.boot.flash.locked    # 0 = unlocked
adb shell getprop sys.oem_unlock_allowed

# ---- Push stock image to device ----
adb push boot.img /sdcard/Download/
adb push init_boot.img /sdcard/Download/  # Android 13+ GKI

# ---- Patch in Magisk app ----
# Magisk → Install → Select and Patch a File → choose image

# ---- Pull patched image ----
adb pull /sdcard/Download/magisk_patched-XXXXX_YYYYY.img .

# ---- Test-boot (non-persistent) ----
adb reboot bootloader
fastboot boot magisk_patched-XXXXX_YYYYY.img

# ---- Flash permanently ----
fastboot flash boot magisk_patched-XXXXX_YYYYY.img        # Android ≤ 12
fastboot flash init_boot magisk_patched-XXXXX_YYYYY.img   # Android 13+ GKI
fastboot flash recovery magisk_patched-XXXXX_YYYYY.img    # no-ramdisk devices

# ---- Flash both A/B slots ----
fastboot flash boot_a magisk_patched-XXXXX_YYYYY.img
fastboot flash boot_b magisk_patched-XXXXX_YYYYY.img

# ---- Disable vbmeta (only if bootloop) ----
fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img

# ---- Reboot ----
fastboot reboot

# ---- Verify root ----
adb shell "su -c 'id'"
adb shell "su -c 'magisk -v'"

  12. 12. Best practices

    • ✅ Always patch the image on the same device where Magisk will be installed [citation:2].
    • ✅ Match the exact build number — mismatched images cause hardware failures.
    • ✅ Use init_boot.img on Android 13+ GKI devices [citation:11].
    • ✅ Test with fastboot boot before flashing permanently, if your OEM supports it [citation:5].
    • ✅ Flash both A/B slots to avoid slot-switch bootloops.
    • ✅ Keep a copy of the stock boot image — you need it for OTA updates.
    • ✅ After OTA updates, re-patch the new build's image (OTA replaces the boot partition) [citation:5].
    • ✅ Disable vbmeta only if the device fails to boot — not as a first step.

Tip: if your device does not have a boot ramdisk (older system-as-root devices), Magisk must hijack the recovery partition. In that case, root is only active when you boot into recovery mode — a special key combo per device is required [citation:2]. For most modern devices, boot.img or init_boot.img is the correct target.
