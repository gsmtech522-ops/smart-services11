How to Unpack & Repack super.img (Dynamic Partitions)

Type
Advanced Guide
Level
Advanced
Time
~20 minutes
Applies to
Android 10+ devices with dynamic partitions (Pixel, Xiaomi, OnePlus, Samsung, Realme)
Last updated
YYYY-MM-DD

Starting with Android 10, Google introduced dynamic partitions. Instead of fixed system, vendor, product, odm, and system_ext partitions, the storage is now organized as a single physical super partition containing multiple logical partitions. The sizes of these logical partitions can be adjusted at flash time. This makes Android updates and GSI (Generic System Image) installs much more flexible — but it also makes extraction more complicated. This guide covers the complete super.img unpack/repack workflow.

Reference

  1. 1. Understanding super.img

    super.img contains a metadata header describing the layout of all logical partitions inside:

    super.img (physical partition)
├── metadata (layout descriptor: slot count, block device size, group definitions)
├── system (logical partition)
├── vendor (logical partition)
├── product (logical partition)
├── odm (logical partition)
├── system_ext (logical partition)
└── (A/B devices have _a and _b copies of each)

    Because the metadata is not a standard filesystem, you cannot mount super.img directly. You must first unpack it into individual partition images.

  2. 2. Prerequisites

    • Linux environment — Ubuntu 20.04+ or WSL2 (Windows Subsystem for Linux).
    • lpunpack and lpmake — part of the android-sdk-libsparse-utils or AOSP system/extras/.
    • simg2img and img2simg — for sparse ↔ raw conversion.
    • At least 20–30 GB free disk for a full unpack/repack cycle.

    Install the tools on Ubuntu / WSL2:

    sudo apt update
sudo apt install android-sdk-libsparse-utils lpunpack lpmake -y

    Verify:

    lpunpack --help
lpmake --help
simg2img --help

  3. 3. Step 1 — Check if super.img is sparse or raw

    Most stock firmware ships super.img as sparse (magic 3A FF 26 ED). lpunpack only handles raw super images, so conversion is usually required.

    Check the file:

    file super.img
xxd -l 4 super.img

    If magic is 3AFF26ED, it is sparse.

    Convert sparse to raw:

    simg2img super.img super_raw.img

    Disk space: a 4 GB sparse super expands to 6–8 GB raw. Ensure enough free disk.

  4. 4. Step 2 — Inspect the super image

    Before extracting, get partition info:

    lpdump super_raw.img

    Output shows all logical partitions with their group, size, and slot:

    Slot 0:
  Metadata version: 10.2
  Metadata size: 764 bytes
  Metadata max size: 65536 bytes
  Slot suffix: _a
  Group: main, size=4294967296
  Block device table: size=4294967296, alignment=1048576, alignment_offset=0
  Partition: system, group=main, size=2147483648
  Partition: vendor, group=main, size=1073741824
  Partition: product, group=main, size=1073741824
Slot 1:
  ...

    Note the exact partition names — system_a, vendor_a, etc. — because lpunpack will use these names when extracting.

  5. 5. Step 3 — Extract logical partitions with lpunpack

    Extract all partitions:

    mkdir -p super_parts
lpunpack --slot=0 super_raw.img super_parts/

    Output files:

    super_parts/
├── system_a.img
├── vendor_a.img
├── product_a.img
├── odm_a.img
├── system_ext_a.img
└── ...

    Extract only a specific partition:

    lpunpack --slot=0 -p system super_raw.img super_parts/

    Extract for slot B (A/B devices):

    lpunpack --slot=1 super_raw.img super_parts/

  6. 6. Step 4 — Modify extracted partitions

    Each extracted partition image is a full filesystem image (ext4 or EROFS). To modify contents:

    Convert sparse to raw if needed:

    simg2img super_parts/system_a.img system_a_raw.img

    Mount and edit ext4:

    sudo mkdir -p /mnt/system
sudo mount -o loop,rw system_a_raw.img /mnt/system
# edit files
sudo umount /mnt/system

    Or extract EROFS:

    sudo fsck.erofs --extract=./system_out system_a_raw.img
# modify files
mkfs.erofs -zlz4hc system_a_new.img ./system_out

    Convert back to sparse (if needed for flashing):

    img2simg system_a_new.img system_a_sparse.img

  7. 7. Step 5 — Repack the new super.img with lpmake

    After modifying partitions, rebuild the super.img with lpmake. You must specify:

    • Device size — the physical size of the super partition (see lpdump output)
    • Metadata size — usually 65536 bytes
    • Metadata slots — 2 (for A/B devices) or 3 (for A/B + snapshot)
    • Group — usually "main" with full size allocation
    • Partitions — each partition with its group, size, and image path

    Basic lpmake example (Pixel 6-style super):

    lpmake --device-size 6442450944 \
  --metadata-size 65536 \
  --metadata-slots 2 \
  --group main:6442450944 \
  --partition system:readonly:2147483648:main \
  --partition vendor:readonly:1073741824:main \
  --partition product:readonly:1073741824:main \
  --partition odm:readonly:524288000:main \
  --partition system_ext:readonly:524288000:main \
  --image system=system_a_new.img \
  --image vendor=vendor_a.img \
  --image product=product_a.img \
  --image odm=odm_a.img \
  --image system_ext=system_ext_a.img \
  --sparse \
  --output super_new.img

    Flags explained:

    • --device-size — the physical partition size (must match your device's actual super partition).
    • --metadata-size — 65536 bytes is standard.
    • --metadata-slots — 2 for A/B, 3 for A/B + virtual snapshots.
    • --group main:size — group name and available size.
    • --partition name:readonly:size:group — define each logical partition.
    • --image name=path — source image for each partition.
    • --sparse — output sparse (for fastboot / SP Flash Tool).
    • --output — final super.img path.

    Size matching: if the total sizes exceed --device-size, lpmake fails. If smaller, it still works but wastes space. Match your device's actual super partition size from lpdump.

  8. 8. Step 6 — Verify and flash

    Verify the new super.img:

    file super_new.img
lpdump super_new.img

    Compare the partition list with the original — it should match except for modified sizes.

    Flash with fastboot:

    # Reboot to fastbootd (userspace fastboot — needed for super flashing)
adb reboot fastboot
fastboot devices

# Flash the new super
fastboot flash super super_new.img

# If A/B device, also flash to slot B
fastboot flash super_b super_new.img

# Reboot
fastboot reboot

    Or flash via SP Flash Tool / Odin depending on your device — place the super.img in the correct firmware folder and flash normally.

  9. 9. Troubleshooting

    ProblemFix
    lpunpack: invalid super headerImage is sparse — run simg2img first .
    lpunpack: no partitions extractedWrong slot selected. Try --slot=1 instead of --slot=0 .
    lpmake: total size exceeds device sizeShrink one partition size, or increase --device-size.
    Fastboot rejects super flashYou are in standard fastboot, not fastbootd. Use adb reboot fastboot .
    Device bootloop after flashingMissing vbmeta match or wrong slot size. Re-flash original super, then retry.
    Cannot read partition metadataPartition might be corrupted or encrypted. Re-extract from firmware.
    Super image is bigger than partitionFlash will fail. Re-run lpmake with a smaller total.

  10. 10. Complete command reference

    # ---- Install tools ----
sudo apt install android-sdk-libsparse-utils lpunpack lpmake -y

# ---- Check sparse vs raw ----
file super.img
xxd -l 4 super.img

# ---- Convert sparse to raw ----
simg2img super.img super_raw.img

# ---- Inspect ----
lpdump super_raw.img

# ---- Extract all partitions (slot A) ----
mkdir -p super_parts
lpunpack --slot=0 super_raw.img super_parts/

# ---- Extract only system ----
lpunpack --slot=0 -p system super_raw.img super_parts/

# ---- Extract slot B ----
lpunpack --slot=1 super_raw.img super_parts/

# ---- Modify a partition (ext4 example) ----
simg2img super_parts/system_a.img system_a_raw.img
sudo mount -o loop,rw system_a_raw.img /mnt/system
# edit files
sudo umount /mnt/system
img2simg system_a_raw.img system_a_sparse.img

# ---- Repack super.img ----
lpmake --device-size 6442450944 \
  --metadata-size 65536 \
  --metadata-slots 2 \
  --group main:6442450944 \
  --partition system:readonly:2147483648:main \
  --partition vendor:readonly:1073741824:main \
  --partition product:readonly:1073741824:main \
  --partition odm:readonly:524288000:main \
  --partition system_ext:readonly:524288000:main \
  --image system=system_a_sparse.img \
  --image vendor=vendor_a.img \
  --image product=product_a.img \
  --image odm=odm_a.img \
  --image system_ext=system_ext_a.img \
  --sparse \
  --output super_new.img

# ---- Flash via fastbootd ----
adb reboot fastboot
fastboot devices
fastboot flash super super_new.img
fastboot reboot

  11. 11. Best practices

    • ✅ Always work on a copy of super.img — never modify the original.
    • ✅ Check if the image is sparse before unpacking.
    • ✅ Note exact partition sizes from lpdump — mismatches break lpmake.
    • ✅ Flash super via fastbootd, not standard fastboot .
    • ✅ Keep the original super.img for recovery if the modified version fails.
    • ✅ Use --sparse output for fastboot; without it, the image can be 2× larger.
    • ✅ After A/B flash, flash both slots or the device will bootloop on slot switch.

Tip: if your goal is only to extract files (e.g. pull an APK from system), you do not need to repack super. Extract with lpunpack, mount the partition, extract the files. Repacking is only needed if you plan to flash the modified super back to the device.
