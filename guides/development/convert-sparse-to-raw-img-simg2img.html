Convert Sparse Image to Raw with simg2img

Type
Technical Guide
Level
Intermediate
Time
~5 minutes
Applies to
Android system.img, vendor.img, super.img, product.img, odm.img
Last updated
YYYY-MM-DD

Android OTA packages and many firmware dumps ship partition images in sparse format — a compressed binary structure that only stores the blocks that actually contain data. Standard tools like 7-Zip, e2fsck, fsck.erofs and most file inspectors cannot read sparse images directly. You must convert them to raw first with simg2img.

Reference

  1. 1. What is a sparse image?

    Google introduced sparse images to reduce OTA size. Instead of writing every byte of a partition, sparse format stores:

    • Headers — describing chunk type and size
    • Data chunks — actual bytes present in the partition
    • Fill chunks — repeated bytes (e.g. zeros) compressed as "fill with 0x00 × N"
    • Skip chunks — blocks that are all zeros and omitted entirely

    A raw system.img might be 4 GB, while its sparse form is often 1–2 GB. Sparse saves disk and download bandwidth, but blocks many tools.

  2. 2. How to identify a sparse image

    Check the first 4 bytes of the file. Sparse magic is 3A FF 26 ED.

    Windows PowerShell:

    $b = [System.IO.File]::ReadAllBytes("C:\firmware\system.img")[0..3]
[System.BitConverter]::ToString($b)

    Output if sparse: 3A-FF-26-ED

    Output if raw ext4: 53-EF appears at offset 1080 (after 1024 bytes of padding).

    Linux / WSL:

    file system.img
xxd -l 16 system.img

    If file says "Android sparse image", it's sparse.

  3. 3. Install simg2img (Windows)

    The easiest route on Windows is the Android SDK Platform Tools alternative — a pre-built simg2img.exe binary.

    Option A — Pre-built Windows binary:

    1. Search GitHub for simg2img windows — many portable builds exist.
    2. Download the ZIP, extract to C:\platform-tools\ or any folder in your PATH.
    3. Verify:
    simg2img.exe --help

    Option B — WSL (recommended for technicians):

    wsl --install -d Ubuntu

    Inside Ubuntu:

    sudo apt update
sudo apt install android-sdk-libsparse-utils -y
which simg2img img2simg

    This installs both simg2img and img2simg system-wide.

    Option C — Build from source (Linux):

    git clone https://github.com/anestisb/android-simg2img.git
cd android-simg2img
make
sudo cp simg2img img2simg /usr/local/bin/

  4. 4. Convert sparse → raw with simg2img

    Basic usage:

    simg2img system.img system_raw.img

    That's it. system_raw.img is now a plain ext4 (or EROFS) filesystem that e2fsck, 7-Zip, mount, and all other tools can read.

    With progress and sparse chunk details:

    simg2img -v system.img system_raw.img

    Multiple images at once:

    for img in *.img; do
  case "$img" in
    *_raw.img) continue ;;
  esac
  simg2img -v "$img" "${img%.img}_raw.img"
done

    Disk space: a 2 GB sparse image can expand to 4–8 GB raw. Ensure you have at least 2× the sparse size free on disk before running the conversion.

  5. 5. Verify the raw image

    After conversion, confirm the raw image is valid:

    file system_raw.img
xxd -l 64 -s 1024 system_raw.img

    For a valid ext4 image, offset 1080 will show 53 EF:

    00000438: 53ef 0100 0000 ...

    Run a quick filesystem check:

    sudo e2fsck -n -f system_raw.img

    For EROFS:

    dump.erofs system_raw.img

    Or just open in 7-Zip — if it opens and shows /system/..., the conversion was successful.

  6. 6. Convert raw → sparse with img2simg

    After modifying a raw image (e.g. adding apps to /system/app), you should convert it back to sparse before flashing — especially if your device's bootloader expects sparse (fastboot flash system requires raw, but SP Flash Tool / Odin handle both; OTA packages always need sparse).

    img2simg system_raw.img system_sparse.img

    Set a custom block size (optional):

    img2simg -b 4096 system_raw.img system_sparse.img

    Default block size (4096) works for most devices. Only change if the target scatter file or fastboot expects a different size.

  7. 7. Working with super.img (dynamic partitions)

    On Android 10+ devices, super.img is a container holding system, vendor, product, odm, system_ext as logical partitions. It's usually sparse.

    Convert to raw:

    simg2img super.img super_raw.img

    Extract individual logical partitions from raw super:

    # Install lpunpack
sudo apt install android-sdk-libsparse-utils lpunpack -y

# Extract all logical partitions
lpunpack super_raw.img ./output_folder/

# This produces:
# system.img  vendor.img  product.img  odm.img  system_ext.img

    Repack a new super.img (advanced):

    # Requires lpmake (part of lpunpack package)
lpmake --device-size 4294967296 \
  --metadata-size 65536 \
  --metadata-slots 2 \
  --group main:4294967296 \
  --partition system:readonly:1073741824:main \
  --partition vendor:readonly:536870912:main \
  --image system=system.img \
  --image vendor=vendor.img \
  --output super_new.img

    Then convert back to sparse:

    img2simg super_new.img super_new_sparse.img

  8. 8. Complete workflow example

    Repacking system.img from an OTA firmware to add a custom app:

    # 1. Verify it's sparse
file system.img                       # "Android sparse image"

# 2. Convert to raw
simg2img system.img system_raw.img

# 3. Verify raw image
file system_raw.img                   # "Linux rev 1.0 ext4 filesystem data"
sudo e2fsck -n -f system_raw.img      # should be clean

# 4. Mount and modify
sudo mkdir /mnt/sysimg
sudo mount -o loop,rw system_raw.img /mnt/sysimg
sudo cp ~/MyApp.apk /mnt/sysimg/system/app/MyApp/MyApp.apk
sudo chmod 644 /mnt/sysimg/system/app/MyApp/MyApp.apk
sudo umount /mnt/sysimg

# 5. Check for corruption after modification
sudo e2fsck -f -y system_raw.img

# 6. Convert back to sparse
img2simg system_raw.img system_modified.img

# 7. Flash to device
fastboot flash system system_modified.img
# or use SP Flash Tool / Odin depending on device

  9. 9. Complete command reference

    # ---- Identify sparse image ----
file system.img
xxd -l 16 system.img               # 3AFF26ED = sparse
xxd -l 4 -s 1080 system.img        # 53EF = ext4 raw

# ---- Install tools ----
sudo apt install android-sdk-libsparse-utils -y
# Also installs: img2simg, simg2img, lpunpack, lpmake

# ---- Sparse → raw ----
simg2img system.img system_raw.img
simg2img -v system.img system_raw.img      # verbose

# ---- Raw → sparse ----
img2simg system_raw.img system_sparse.img
img2simg -b 4096 system_raw.img system_sparse.img

# ---- Verify raw image ----
file system_raw.img
sudo e2fsck -n -f system_raw.img           # ext4
dump.erofs system_raw.img                  # EROFS

# ---- Mount and modify (Linux only) ----
sudo mkdir /mnt/sysimg
sudo mount -o loop,rw system_raw.img /mnt/sysimg
# ... modify files ...
sudo umount /mnt/sysimg

# ---- super.img (dynamic partitions) ----
simg2img super.img super_raw.img
lpunpack super_raw.img ./output/
# modify system.img inside output/
lpmake --device-size ... --output super_new.img ...
img2simg super_new.img super_new_sparse.img

# ---- Windows only (simg2img.exe) ----
simg2img.exe system.img system_raw.img
img2simg.exe system_raw.img system_sparse.img

  10. 10. Troubleshooting

    ProblemFix
    simg2img: invalid sparse magicImage is not actually sparse — it might be raw already, or truncated. Check with xxd.
    simg2img: cannot allocate memoryNot enough RAM. Use a machine with more memory, or increase swap.
    simg2img: cannot write outputNot enough disk space. Raw image can be 2× the sparse size.
    e2fsck: Bad magic numberRaw image is not ext4 — could be EROFS. Use dump.erofs.
    Output image opens but has no filesImage is sparse + empty — convert failure, or the source was already corrupted.
    Windows simg2img.exe hangsFile is too big for 32-bit binary. Use the 64-bit build or WSL.
    lpunpack: invalid super headerConvert to raw first with simg2img — lpunpack only reads raw super images.
    Flash fails with "invalid sparse file"You're trying to flash raw where fastboot expects sparse (or vice versa). Convert with img2simg if needed.
    Modifications don't survive rebootdm-verity is active — disable verity/vbmeta first (see DM-Verity guide).

  11. 11. Best practices

    • ✅ Always keep the original sparse image — never overwrite it.
    • ✅ Verify free disk space before conversion (raw ≈ 2× sparse).
    • ✅ Use simg2img -v for progress visibility on large files.
    • ✅ Check raw image with file before mounting.
    • ✅ Run e2fsck -n (check-only) first after every modification.
    • ✅ Convert back to sparse with img2simg when flashing via SP Flash Tool or OTA.
    • ✅ For super.img, use lpunpack + lpmake — do not treat as a single ext4.
    • ✅ Test on a copy, never on the only working image.

Tip: if you're on Windows and don't want to install WSL, many repair technicians use the portable simg2img.exe built from the Android source — place it in your Platform Tools folder alongside adb.exe and fastboot.exe for a one-stop toolchain.
