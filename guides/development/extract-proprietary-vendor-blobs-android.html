How to Extract Proprietary Vendor Blobs from Android Firmware

Type
Developer Guide
Level
Advanced
Time
~30 minutes
Applies to
Custom ROM developers, device tree maintainers, advanced technicians
Last updated
YYYY-MM-DD

When building a custom ROM (LineageOS, Pixel Experience, crDroid) or a device tree, the open-source Android framework alone is not enough. Your device also needs the proprietary vendor blobs — the closed-source binaries supplied by the OEM/chipset vendor that make your specific hardware work:

  • Camera HALs (Sony, Samsung ISOCELL, Omnivision)
  • GPU drivers (Adreno, Mali)
  • Baseband / RIL (Qualcomm, MediaTek modem)
  • Audio HALs (Qualcomm Aqstic, Dolby, Dirac)
  • Sensor HALs (accelerometer, gyro, proximity)
  • Fingerprint HAL (Goodix, FPC, Synaptics)
  • Wi-Fi/BT firmware (Broadcom, Qualcomm, MediaTek)
  • DRM (Widevine L1), biometrics, and codec libraries

This guide shows how to extract those blobs from your device's vendor.img, system.img, odm.img, or super.img and organize them into a proper device tree.

Reference

  1. 1. What are vendor blobs?

    Vendor blobs are the shared library files (.so), firmware files (.bin, .fw), executables, and configuration files that implement the Hardware Abstraction Layer (HAL) between Android's framework and your device's physical hardware.

    Blob typeLocationExample
    Camera HAL/vendor/lib64/hw/camera.*.socamera.qcom.so
    GPU driver/vendor/lib64/egl/libGLESv2_adreno.so
    Audio HAL/vendor/lib64/hw/audio.*.soaudio.primary.default.so
    RIL (radio)/vendor/lib64/libril*.solibril-qc-qmi-1.so
    Sensors HAL/vendor/lib64/hw/sensors.*.sosensors.ssc.so
    Fingerprint/vendor/lib64/hw/fingerprint.*.sofingerprint.goodix.so
    Wi-Fi/BT firmware/vendor/firmware/wlan.elf, bt_fw.bin

  2. 2. Prerequisites

    • Linux PC (Ubuntu 20.04/22.04 recommended) — Windows workflows are painful for this.
    • Full stock firmware for your device (from the OTA or vendor site).
    • Partition images: vendor.img, system.img, odm.img, or super.img.
    • Tools: simg2img, lpunpack, 7-Zip, erofs-utils, ext4fuse, git.
    • At least 20 GB free disk.

    Install tools on Ubuntu:

    sudo apt update
sudo apt install -y android-sdk-libsparse-utils \
  erofs-utils ext4fuse git python3 python3-pip
pip3 install payload_dumper

  3. 3. Step 1 — Prepare the vendor image

    Depending on your firmware format, your vendor.img may be:

    • Sparse (magic 3A FF 26 ED) → convert to raw first.
    • Inside super.img (dynamic partitions) → extract with lpunpack.
    • Already raw ext4 → ready to mount.

    Check file type:

    file vendor.img
xxd -l 4 vendor.img

    If sparse, convert:

    simg2img vendor.img vendor_raw.img

    If inside super.img, extract:

    simg2img super.img super_raw.img
mkdir super_parts
lpunpack super_raw.img super_parts/

    This yields vendor.img, system.img, product.img, odm.img, system_ext.img.

  4. 4. Step 2 — Mount the vendor image

    Vendor images are typically ext4. Mount them read-only to explore the filesystem:

    ext4 (most common):

    sudo mkdir -p /mnt/vendor
sudo mount -o loop,ro vendor_raw.img /mnt/vendor
ls /mnt/vendor

    EROFS (Android 11+ on some devices):

    sudo mkdir -p /mnt/vendor
sudo mount -t erofs -o loop,ro vendor_raw.img /mnt/vendor

    If kernel does not support EROFS mount:

    mkdir -p ./vendor_extracted
fsck.erofs --extract=./vendor_extracted vendor_raw.img

    Windows only (read-only via WSL):

    wsl --mount --vhd vendor_raw.img --bare
# or use 7-Zip to open ext4 read-only

  5. 5. Step 3 — Explore the vendor directory

    Key folders inside a mounted /vendor:

    vendor/
├── bin/                → vendor executables (ril-daemon, etc.)
├── etc/                → config files (audio_policy, camera_config)
├── firmware/           → Wi-Fi/BT/modem firmware files (.elf, .bin)
├── lib/                → 32-bit native libs
├── lib64/              → 64-bit native libs
│   ├── hw/             → HAL implementations (camera.*.so, sensors.*.so)
│   ├── egl/            → GPU drivers (libGLESv2_*.so)
│   └── soundfx/        → audio effects
├── app/                → vendor apps (Camera, permissions)
├── overlay/            → RRO overlays for system
├── build.prop          → vendor build properties
└── manifest.xml        → HAL service registration

    List HAL implementations:

    ls -la /mnt/vendor/lib64/hw/
ls -la /mnt/vendor/lib/hw/

    Look for camera, GPU, and radio libs:

    find /mnt/vendor -name "*camera*" -o -name "*adreno*" -o -name "*libril*" | head -30

  6. 6. Step 4 — Identify needed blobs

    For a custom ROM, only the blobs your device tree needs are important. The standard reference is LineageOS extract-files.sh or the device's proprietary-blobs.txt:

    Approach A — Use the device tree's blob list:

    1. Find your device's tree on GitHub: e.g. github.com/LineageOS/android_device_<vendor>_<device>
    2. Look for proprietary-files.txt in the root.
    3. Each line specifies a blob: -vendor/lib64/hw/camera.qcom.so (leading - means strip the vendor prefix when placed in vendor partition).

    Approach B — Auto-generate the list from vendor.img:

    Compare with system.img to find blobs not present in AOSP:

    sudo mount -o loop,ro system_raw.img /mnt/system
comm -23 \
  <(find /mnt/vendor -type f -name '*.so' -printf '%P\n' | sort) \
  <(find /mnt/system -type f -name '*.so' -printf '%P\n' | sort) \
  > vendor_only_libs.txt
cat vendor_only_libs.txt | head -20

    This lists vendor libraries that have no AOSP equivalent — prime candidates for extraction.

  7. 7. Step 5 — Extract blobs

    Create the output device tree structure:

    mkdir -p proprietary/vendor/{lib,lib64,etc,bin,firmware,app}
mkdir -p proprietary/vendor/lib/hw
mkdir -p proprietary/vendor/lib64/hw
mkdir -p proprietary/vendor/lib64/egl

    Copy files manually:

    # Copy the entire vendor tree
sudo cp -a /mnt/vendor/. ./proprietary/vendor/

# Or specific files only
sudo cp /mnt/vendor/lib64/hw/camera.qcom.so ./proprietary/vendor/lib64/hw/
sudo cp -r /mnt/vendor/firmware/ ./proprietary/vendor/firmware/
sudo cp /mnt/vendor/etc/camera/ -r ./proprietary/vendor/etc/

    Or use a proper extractor script (recommended for maintainers):

    LineageOS provides extract_utils/extract_files.py which reads proprietary-files.txt and creates the correct tree from mounted images automatically:

    git clone https://github.com/LineageOS/android_tools_extract-utils.git
cd android_tools_extract-utils
python3 extract_files.py \
  -s /mnt/vendor \
  -d /mnt/system \
  --kang \
  -o /path/to/device_tree

    This produces a tree ready for vendor.mk and Android.bp.

  8. 8. Step 6 — Check dependencies

    Vendor blobs often depend on other vendor blobs. Missing dependencies = silent crashes at boot.

    Check a library's dependencies:

    readelf -d /mnt/vendor/lib64/hw/camera.qcom.so | grep NEEDED

    Output lists all libXXX.so files this blob requires. Ensure each of these also exists in proprietary/vendor/lib64/ or AOSP's system/lib64/.

    Run a full dependency scan:

    for lib in proprietary/vendor/lib64/*.so; do
  echo "=== $lib ==="
  readelf -d "$lib" 2>/dev/null | grep NEEDED | awk '{print $NF}'
done

    Missing dependencies cause: black screen, camera FC (force close), no audio, bootloop at zygote. Always resolve dependency chains before building.

  9. 9. Step 7 — Organize into a device tree

    Structure the extracted blobs for a device tree:

    device/myphone/mydevice/
├── Android.bp
├── Android.mk
├── BoardConfig.mk
├── device.mk
├── proprietary-files.txt
├── vendorsetup.sh
├── extract-files.sh
├── system.prop
└── proprietary/
    └── vendor/
        ├── lib/
        ├── lib64/
        ├── etc/
        ├── bin/
        ├── firmware/
        └── app/

    Sample entry in proprietary-files.txt:

    -vendor/lib64/hw/camera.qcom.so
-vendor/lib64/hw/camera.qcom.so:32
-vendor/lib64/hw/sensors.ssc.so
-vendor/lib64/libril-qc-qmi-1.so
-vendor/etc/camera/camera_config.xml
-vendor/firmware/wlan.elf

    The :32 suffix indicates a 32-bit blob (usually lib/ instead of lib64/).

    Sample entry in vendor.mk:

    PRODUCT_COPY_FILES += \
  $(LOCAL_PATH)/proprietary/vendor/etc/camera/camera_config.xml:$(TARGET_COPY_OUT_VENDOR)/etc/camera/camera_config.xml \
  $(LOCAL_PATH)/proprietary/vendor/firmware/wlan.elf:$(TARGET_COPY_OUT_VENDOR)/firmware/wlan.elf

PRODUCT_PACKAGES += \
  camera.qcom \
  sensors.ssc \
  libril-qc-qmi-1

  10. 10. Step 8 — Vendor overlay (optional)

    Extract the vendor's build.prop and convert it into system.prop or vendor.prop overrides in your device tree:

    grep -E '^(ro\.|persist\.)' /mnt/vendor/build.prop > proprietary/vendor.prop

    Add overrides in device.mk:

    TARGET_SYSTEM_PROP += $(LOCAL_PATH)/proprietary/vendor.prop

  11. 11. Verify the extracted blobs

    Before building, verify integrity:

    Check each blob is a valid ELF shared library:

    find proprietary/vendor -name "*.so" -exec file {} \; | grep -v "ELF"

    Any output (non-ELF files) means a corrupted extraction.

    Check architecture matches target:

    file proprietary/vendor/lib64/*.so | head -5
# ARM aarch64 = 64-bit arm
# ARM 32-bit = for lib/ (32-bit) folder

    Verify symbols are exported:

    nm -D proprietary/vendor/lib64/hw/camera.qcom.so | grep " T " | head -5

    If you see exported function symbols (T), the ELF is intact.

  12. 12. Troubleshooting

    ProblemFix
    Mount fails with "unknown filesystem type"Image is EROFS or sparse. Convert with simg2img, or use fsck.erofs.
    Camera FC after custom ROMMissing dependency or missing /vendor/etc/camera/ config folder.
    No audio in custom ROMMissing audio_policy_configuration.xml or audio.primary.*.so.
    Bootloop at zygoteMissing manifest.xml or HAL service registration.
    Fingerprint not workingMissing fingerprint.*.so HAL + persist partition data.
    readelf shows NEEDED libs missingCopy the missing dependencies recursively.
    Blobs won't compileWrong path — check whether the blob belongs in system/ or vendor/.
    Widevine L1 lostMissing libwvhidl.so + liboemcrypto.so + TEE blobs.

  13. 13. Complete command reference

    # ---- Install tools ----
sudo apt install android-sdk-libsparse-utils erofs-utils git python3-pip
pip3 install payload_dumper

# ---- Extract from super.img ----
simg2img super.img super_raw.img
mkdir super_parts
lpunpack super_raw.img super_parts/

# ---- Convert sparse vendor ----
simg2img vendor.img vendor_raw.img

# ---- Mount vendor (ext4) ----
sudo mkdir -p /mnt/vendor
sudo mount -o loop,ro vendor_raw.img /mnt/vendor

# ---- Mount vendor (EROFS) ----
sudo mount -t erofs -o loop,ro vendor_raw.img /mnt/vendor

# ---- Extract EROFS via fsck ----
fsck.erofs --extract=./vendor_extracted vendor_raw.img

# ---- Explore ----
ls /mnt/vendor/lib64/hw/
ls /mnt/vendor/firmware/
find /mnt/vendor -name "*camera*" -o -name "*ril*"

# ---- Copy blobs ----
mkdir -p proprietary/vendor/lib64/hw
sudo cp /mnt/vendor/lib64/hw/camera.qcom.so proprietary/vendor/lib64/hw/
sudo cp -a /mnt/vendor/firmware/ proprietary/vendor/firmware/

# ---- Verify ----
file proprietary/vendor/lib64/hw/*.so
readelf -d proprietary/vendor/lib64/hw/camera.qcom.so | grep NEEDED
nm -D proprietary/vendor/lib64/hw/camera.qcom.so | grep " T "

# ---- Auto-extract via LineageOS utils ----
git clone https://github.com/LineageOS/android_tools_extract-utils.git
python3 extract_files.py -s /mnt/vendor -d /mnt/system -o ./device_tree

# ---- Unmount ----
sudo umount /mnt/vendor

  14. 14. Best practices

    • ✅ Work in Linux — WSL is possible but slow for large extractions.
    • ✅ Use the exact stock firmware matching your current build.
    • ✅ Check dependencies with readelf -d before building.
    • ✅ Keep proprietary-files.txt in sync with extracted blobs.
    • ✅ Store the extraction tree in git — makes regressions easy to trace.
    • ✅ Match bitness: lib/ = 32-bit ARM, lib64/ = 64-bit aarch64.
    • ✅ Re-extract after every firmware update — blobs change.
    • ✅ Never use someone else's extracted blobs on your device — could break IMEI or security.

Tip: a well-organized device tree can be built entirely from extract-files.sh + proprietary-files.txt. Maintainers usually ship those two scripts and no binary blobs — the blobs are extracted from the device at build time. If you are new to device trees, start with LineageOS device wiki to find one matching your model.
