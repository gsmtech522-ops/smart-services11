How to Check & Repair system.img File System on Windows

Type
Technical Guide
Level
Advanced
Time
~20 minutes
Applies to
Ext4 / EROFS / sparse Android system.img files
Last updated
YYYY-MM-DD

When you extract system.img from a stock firmware or readback dump, you often need to verify its integrity, mount it to inspect contents, or repair it if it's corrupted. Windows does not natively support ext4 or EROFS filesystems, so you need dedicated tools. This guide covers the complete workflow — from identifying the filesystem type to running e2fsck for repair.

Reference

  1. 1. Identify the filesystem type first

    Android uses several filesystem formats. Before anything else, figure out what you're dealing with:

    TypeDetection methodTool needed
    ext4File starts with magic bytes at offset 0x438 = 53 EFe2fsck, 7-Zip, LinuxReader
    EROFSFile starts with E2 E1 F5 E0 at offset 0x400 (1024)erofs-utils, 7-Zip ZS
    Sparse ext4Starts with magic 3A FF 26 EDsimg2img first, then ext4 tools
    F2FSMagic F2 F5 20 at offset 0x400fsck.f2fs (Linux)
    Raw / unknownNo recognizable magichex editor to inspect

    Quick detection via PowerShell:

    $bytes = [System.IO.File]::ReadAllBytes("C:\firmware\system.img")[1024..1027]
[System.BitConverter]::ToString($bytes)

    Output examples:

    • 53-EF at offset 1080 → ext4
    • E2-E1-F5-E0 → EROFS
    • 3A-FF-26-ED → sparse ext4

  2. 2. Method 1 — Verify ext4 with e2fsck (Linux/WSL)

    e2fsck is the standard ext2/3/4 filesystem check and repair tool. Windows has no native version, so use WSL (Windows Subsystem for Linux) or a Linux VM.

    Step 1 — Install WSL (once):

    wsl --install -d Ubuntu

    Reboot and complete Ubuntu setup.

    Step 2 — Install e2fsprogs:

    sudo apt update
sudo apt install e2fsprogs android-sdk-libsparse-utils -y

    Step 3 — Copy system.img into WSL and check:

    # Copy file into WSL home
cp /mnt/c/firmware/system.img ~/system.img

# Check-only mode (no changes)
sudo e2fsck -n -f ~/system.img

    Step 4 — Repair if errors are found:

    sudo e2fsck -f -y ~/system.img

    Flags explained:

    • -n → check only (no writes) — safe
    • -f → force check even if clean
    • -y → answer "yes" to all repairs
    • -p → automatic safe repair
    • -v → verbose output

    WSL limitation: WSL mounts the Windows drive under /mnt/c with special permissions. Always copy the image into the WSL home folder first — do not run e2fsck directly on /mnt/c/... paths.

  3. 3. Method 2 — Convert sparse ext4 before checking

    If your system.img starts with sparse magic (3A FF 26 ED), it's a "sparse image" — a compressed format used by OTA packages. e2fsck cannot read it directly.

    Step 1 — Convert to raw ext4:

    simg2img system.img system_raw.img

    Step 2 — Then run e2fsck:

    sudo e2fsck -f -y ~/system_raw.img

    Step 3 — Convert back to sparse (optional):

    img2simg system_raw.img system_fixed.img

  4. 4. Method 3 — Inspect contents with 7-Zip / LinuxReader (ext4)

    You don't always need to repair — sometimes you just want to verify the file isn't corrupted and see what's inside.

    Option A — 7-Zip:

    1. Right-click system.img in Windows Explorer.
    2. Choose 7-Zip → Open archive.
    3. If it opens and shows /system/... folders, the file is intact.
    4. Extract individual files by right-clicking → Extract.

    Note: 7-Zip supports ext4 read-only. It cannot repair. If the image opens but you see random garbage, the file is corrupt.

    Option B — LinuxReader (DiskInternals):

    1. Download and install LinuxReader (free).
    2. Open the tool → Open Image → select system.img.
    3. Browse the filesystem. Extract files if needed.
    4. LinuxReader can also show partition table info — useful to know if the image is raw or sparse.

  5. 5. Method 4 — EROFS check (Android 11+)

    Modern Android (11+) often ships system.img as EROFS instead of ext4. EROFS is read-only; you cannot run e2fsck on it, but you can still inspect it.

    Install erofs-utils in WSL:

    sudo apt install erofs-utils -y

    List contents without mounting:

    fsck.erofs --extract=/tmp/system_extracted ~/system.img

# Or just inspect superblock:
dump.erofs ~/system.img

    Extract a single folder:

    fsck.erofs --extract=/tmp/out --path=/system/app ~/system.img

    If EROFS extraction succeeds, the filesystem is structurally valid — no repair needed. If it throws "invalid magic" or "corrupted superblock", the image is bad.

  6. 6. Method 5 — Check partition table & size

    A "corrupt" system.img is often just truncated — its size doesn't match the partition it's supposed to fit. Verify this before running repair tools:

    Check file size in Windows:

    (Get-Item "C:\firmware\system.img").Length / 1MB

    Check scatter file expected size (MTK):

    Open the Android_scatter.txt file in Notepad → find partition_name: system → note the partition_size value. Convert hex to decimal to compare.

    Check ext4 superblock info in WSL:

    sudo tune2fs -l ~/system.img

    Look at Block count × Block size — this should match the file size. If not, the file is corrupted or truncated.

  7. 7. Method 6 — Mount & write to system.img (advanced)

    To actually modify a system.img (add/remove system apps), you need to mount it in Linux:

    Create a mount point and loop-mount:

    mkdir /mnt/sysimg
sudo mount -o loop,rw ~/system.img /mnt/sysimg

    If mount fails with "already mounted" or "read-only":

    sudo mount -o loop,rw,remount ~/system.img /mnt/sysimg

    Make modifications, then unmount:

    cp ~/my_app.apk /mnt/sysimg/system/app/MyApp/MyApp.apk
sudo umount /mnt/sysimg

    WSL limitation: loop-mounting requires kernel modules that standard WSL2 does not include. Use a full Ubuntu VM (VirtualBox / VMware) or a live Linux USB for this method.

  8. 8. Method 7 — Quick integrity check with md5 / sha256

    The fastest way to verify a system.img is intact is to compare its hash against the original firmware manifest (many stock ROMs ship a checksum.md5 or checksums.txt):

    # Windows PowerShell
Get-FileHash "C:\firmware\system.img" -Algorithm SHA256
    # WSL / Linux
sha256sum system.img
md5sum system.img

    If the hash matches the manifest, the image is byte-for-byte correct — no repair needed. If not, re-download or extract again.

  9. 9. Complete command reference

    # ---- Detect filesystem type ----
file system.img
xxd -l 64 -s 1024 system.img

# ---- Convert sparse to raw ----
simg2img system.img system_raw.img
img2simg system_raw.img system_sparse.img

# ---- ext4 check & repair ----
sudo e2fsck -n -f system.img       # check only
sudo e2fsck -f -y system.img       # repair
sudo tune2fs -l system.img         # superblock info

# ---- EROFS inspect ----
dump.erofs system.img
fsck.erofs --extract=/tmp/out system.img

# ---- Mount and modify ----
sudo mkdir /mnt/sysimg
sudo mount -o loop,rw system.img /mnt/sysimg
# ... modify files ...
sudo umount /mnt/sysimg

# ---- Hash verification ----
sha256sum system.img
md5sum system.img

# ---- Windows-only alternatives ----
# 7-Zip: right-click image → Open archive
# LinuxReader: Open Image → select system.img

  10. 10. Troubleshooting

    ProblemFix
    7-Zip says "Cannot open file as archive"Image is sparse or EROFS, not ext4. Convert with simg2img first, or use dump.erofs.
    e2fsck: "Bad magic number in super-block"Image is not ext4, or is corrupted. Check first 1024 bytes with hex editor.
    e2fsck: "Filesystem still has errors"Run e2fsck -f -y -c to re-scan for bad blocks, or e2fsck -p for auto-safe.
    e2fsck: "Superblock last mount time is in the future"Clock skew — safe to answer "yes" to fix.
    WSL cannot find /mnt/cWindows drive mounting is disabled. Enable in /etc/wsl.conf → [automount] enabled=true.
    Loop mount fails in WSLUse Ubuntu VM (VirtualBox/VMware) or live Linux USB.
    Extracted app doesn't run after reinjectMissing SELinux contexts. Use set_metadata_recursive in updater-script or fix permissions in mounted fs.
    EROFS fsck.erofs throws errorImage is truncated or corrupted. Re-download from official source.

  11. 11. Best practices

    • ✅ Always verify hash against firmware manifest before repairing.
    • ✅ Work on a copy — never repair the original in place.
    • ✅ Use e2fsck -n (check-only) first before running any repair.
    • ✅ Copy the image into WSL home directory before running e2fsck.
    • ✅ Keep a copy of the original system.img before modifications.
    • ✅ Test modifications in a VM before flashing back to a physical device.
    • ✅ After modifying, re-hash and compare to ensure no unintended changes.

Tip: most "corrupt system.img" reports are actually the wrong file format (sparse vs raw) or a truncated download. Verify file type and hash before running repair tools — they can actually cause more damage if the image was fine.
