How to Unpack & Repack Android boot.img / recovery.img

Type
Advanced Guide
Level
Advanced
Time
~15 minutes
Applies to
All Android boot/recovery images (AOSP, GKI, vendor_boot)
Last updated
YYYY-MM-DD

Android's boot.img and recovery.img are not simple archives — they are structured binary images containing a kernel, a ramdisk (cpio archive), device tree blobs (DTB), and metadata headers. To modify the ramdisk (e.g. add an init script, patch init.rc, or replace adbd), you must properly unpack and repack the image. This guide covers the two most reliable tools: Android Image Kitchen (AIK) and magiskboot.

Reference

  1. 1. What's inside boot.img / recovery.img?

    ComponentContent
    HeaderImage format version, page size, offsets, sizes
    KernelLinux kernel binary (often compressed)
    Ramdiskcpio archive containing /init, /sbin/adbd, /etc/init.rc
    SecondOptional second-stage bootloader
    DTBDevice Tree Blob (hardware description)

    Android 13+ GKI devices: the kernel lives in boot.img but the ramdisk lives in init_boot.img. Patch init_boot.img for ramdisk changes on these devices.

  2. 2. Prerequisites

    • Stock boot.img or recovery.img matching your exact build number.
    • AIK (Android Image Kitchen) — Windows, Linux or macOS package [citation:4].
    • Or magiskboot (comes with Magisk, or download separately) [citation:7].
    • A Linux environment (WSL2 is fine) for the most reliable results.
    • Backup of the original image — never overwrite it.

  3. 3. Method 1 — Android Image Kitchen (AIK) — recommended

    AIK is the industry standard for unpacking and repacking boot/recovery images. It preserves the original format, compression, and offsets [citation:4].

    Step 1 — Download and extract AIK:

    • Get the AIK package for your OS (Windows ZIP includes batch scripts).
    • Extract to a folder, e.g. C:\AIK\.

    Step 2 — Unpack the image:

    On Windows: drag boot.img onto unpackimg.bat.

    On Linux/WSL:

    cd ~/AIK
./unpackimg.sh /path/to/boot.img

    Step 3 — Examine the unpacked output:

    split_img/
├── boot.img-kernel
├── boot.img-ramdisk.cpio.gz
├── boot.img-dtb
├── boot.img-second
└── boot.img-header

ramdisk/
├── init
├── init.rc
├── sbin/
├── etc/
└── ...

    Step 4 — Modify files inside ramdisk/:

    • Edit init.rc to add services or change properties.
    • Replace adbd with a custom version.
    • Add scripts under /sbin/.

    Step 5 — Repack the image:

    On Windows: double-click repackimg.bat.

    On Linux/WSL:

    ./repackimg.sh

    AIK produces image-new.img in the AIK directory. Rename it to boot_new.img.

    AIK caveat: AIK prepares images but does not validate device-specific signing, bootloader, or verified-boot requirements [citation:4]. Flash only on an unlocked bootloader and test with fastboot boot first.

  4. 4. Method 2 — magiskboot (official Magisk tool)

    magiskboot is Magisk's built-in unpack/repack tool. It parses headers, detects compression, and preserves the original format on repack [citation:7].

    Step 1 — Get magiskboot:

    • On a rooted device: /data/adb/magisk/magiskboot.
    • On PC: extract from the Magisk APK (it's inside the lib/ folder).

    Step 2 — Unpack:

    cd /path/to/boot_folder
magiskboot unpack boot.img

    Output files: kernel, ramdisk.cpio, second, dtb, extra [citation:7].

    Step 3 — Modify the ramdisk:

    ramdisk.cpio is a cpio archive. You can extract it:

    mkdir ramdisk_out
cd ramdisk_out
cpio -idmv < ../ramdisk.cpio

    Edit files, then repack the cpio:

    find . | cpio -o -H newc > ../ramdisk_new.cpio
cd ..
mv ramdisk_new.cpio ramdisk.cpio

    Step 4 — Repack:

    magiskboot repack boot.img new-boot.img

    The original header and compression are preserved; only the modified ramdisk is replaced [citation:7].

  5. 5. Method 3 — Carliv Image Kitchen (Windows GUI)

    Carliv Image Kitchen is a Windows-native GUI alternative to AIK. It supports Android 10–14, AVB 2.0, dynamic partitions, and GKI [citation:8].

    1. Download and extract Carliv Image Kitchen.
    2. Drag boot.img into the tool window.
    3. Click Unpack — it produces kernel, ramdisk.cpio, dtb, second.
    4. Modify files as needed.
    5. Click Repack to generate a new image.

    Why choose Carliv: it avoids Cygwin/WSL compatibility issues and Windows NTFS permission loss that can break the ramdisk [citation:8].

  6. 6. Verification before flashing

    After repacking, verify the new image is valid:

    # Compare size
ls -l boot.img new-boot.img

# Check header magic (should be ANDROID!)
xxd -l 8 new-boot.img

# Unpack again to verify integrity
mkdir verify && cd verify
magiskboot unpack ../new-boot.img
ls -la

    If unpacking succeeds without error, the image structure is intact.

  7. 7. Flashing the new image

    Test without permanent write (recommended):

    adb reboot bootloader
fastboot boot new-boot.img

    If the device boots successfully, flash permanently:

    fastboot flash boot new-boot.img

# For recovery
fastboot flash recovery new-recovery.img

# For Android 13+ GKI
fastboot flash init_boot new-init_boot.img

    Bootloop risk: if the repacked image fails to boot, re-flash the stock boot image immediately. Keep a copy of the original boot.img in a safe folder.

  8. 8. Troubleshooting

    ProblemFix
    AIK: "Unsupported format"Image is not a standard boot image (could be vendor_boot or GKI). Use the matching unpacker.
    AIK repack produces a larger imageCompression level differs. AIK preserves original compression where possible, but ramdisk changes affect size.
    magiskboot unpack failsImage is corrupted or an unsupported format. Try AIK instead.
    Device bootloop after flashAVB rejected the modified image. Disable verity/vbmeta or re-sign the image.
    Ramdisk changes don't applyOn Android 13+, ramdisk is in init_boot.img, not boot.img.
    Windows AIK batch script failsRun as Administrator; ensure path has no spaces.
    Carliv can't find kernelImage might be vendor_boot with a different structure. Use AIK with explicit flags.

  9. 9. Complete command reference

    # ---- AIK (Linux/WSL) ----
cd ~/AIK
./unpackimg.sh /path/to/boot.img
# edit ramdisk/ files
./repackimg.sh
# output: image-new.img

# ---- AIK (Windows) ----
# Drag boot.img onto unpackimg.bat
# Edit ramdisk/ folder
# Double-click repackimg.bat

# ---- magiskboot ----
magiskboot unpack boot.img
# files: kernel, ramdisk.cpio, dtb, second, extra

# Extract ramdisk cpio
mkdir rd && cd rd
cpio -idmv < ../ramdisk.cpio
# edit files
find . | cpio -o -H newc > ../ramdisk_new.cpio
cd .. && mv ramdisk_new.cpio ramdisk.cpio

# Repack
magiskboot repack boot.img new-boot.img

# ---- Verify ----
xxd -l 8 new-boot.img         # should show ANDROID!
mkdir verify && cd verify
magiskboot unpack ../new-boot.img

# ---- Flash ----
fastboot boot new-boot.img     # test
fastboot flash boot new-boot.img

  10. 10. Best practices

    • ✅ Always keep an untouched copy of the original image.
    • ✅ Use AIK for stability — it preserves original format and compression [citation:4].
    • ✅ Use magiskboot for scripted/automated workflows [citation:7].
    • ✅ Test with fastboot boot before flashing permanently.
    • ✅ On Android 13+ GKI, patch init_boot.img for ramdisk changes.
    • ✅ Disable vbmeta/verity if the device rejects the modified image.
    • ✅ Repack on the same build's original image — mismatched headers cause bootloops.

Tip: if you're modifying the ramdisk to add a script or patch init.rc, AIK is the safest choice. It records original offsets and compression parameters, so the repacked image is structurally identical to the stock one. Only the ramdisk contents change.
