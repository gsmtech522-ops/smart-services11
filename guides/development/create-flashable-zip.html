Create a Custom Flashable ZIP for MTK & Unisoc Devices

Type
Developer Guide
Level
Advanced
Time
~20 minutes
Applies to
MediaTek & Unisoc / Spreadtrum devices with TWRP/OrangeFox
Last updated
YYYY-MM-DD

Custom recoveries like TWRP, OrangeFox, or PitchBlack let you modify system environments instantly. Instead of flashing single partitions one by one, you can pack modifications into one flashable ZIP and install via recovery — perfect for boot animations, pre-installed system apps, or raw partition images (boot.img, recovery.img) on MediaTek (MTK) and Unisoc/SPD platforms.

Reference

  1. 1. Anatomy of a flashable ZIP

    Every flashable ZIP must have this exact directory tree:

    Your_Custom_Patch.zip
├── META-INF/
│   └── com/
│       └── google/
│           └── android/
│               ├── update-binary
│               └── updater-script      <-- core code lives here
├── system/                             (optional - push files)
└── boot.img / recovery.img             (optional - flash raw images)
    • update-binary: compiled executable that interprets recovery instructions.
    • updater-script: plain text in Edify language — tells recovery what files to copy, where to map partitions, and what permissions to set.

  2. 2. Step 1 — Obtain the base META structure

    Don't compile update-binary yourself. Extract the working META-INF folder from a light patch or Magisk installer ZIP.

    1. Create an empty folder on Desktop: MyFlashablePatch.
    2. Inside, create META-INF/com/google/android/.
    3. Place a compatible update-binary file inside.

  3. 3. Step 2 — Write updater-script

    Create a blank text file inside META-INF/com/google/android/ and name it exactly updater-script (remove .txt extension). Open with Notepad++ to write commands.

    Scenario A — Flash raw image (boot/recovery) on MTK:

    ui_print("=================================");
ui_print(" Flashing Boot Image for MTK ");
ui_print("=================================");
package_extract_file("boot.img", "/dev/block/by-name/boot");
ui_print("Success! Boot partition restored.");

    Scenario A — Unisoc / SPD devices:

    ui_print("=================================");
ui_print(" Deploying Unisoc Patch ");
ui_print("=================================");
package_extract_file("boot.img", "/dev/block/by-name/boot");

    Scenario B — Push system files (apps, animations):

    ui_print("Mounting System Partitions...");
mount("ext4", "EMMC", "/dev/block/by-name/system", "/system");
package_extract_dir("system", "/system");
set_metadata_recursive("/system/media", "uid", 0, "gid", 0, "fmode", 0644, "dmode", 0755);
unmount("/system");
ui_print("System update injected successfully!");

  4. 4. Step 3 — Populate custom files

    Inside MyFlashablePatch:

    • Scenario A: copy your boot.img or recovery.img here.
    • Scenario B: create a system/ folder and mirror the target path (e.g. system/media/bootanimation.zip).

  5. 5. Step 4 — Compress correctly (crucial)

    TWRP is sensitive to compression. Wrong settings trigger "Error 7" or "Invalid ZIP file zone".

    1. Select all items inside the folder (META-INF + others) — not the parent folder itself.
    2. Right-click → Add to archive…
    3. Format: strictly ZIP.
    4. Compression: Normal or Store (never Ultra / Maximum).
    5. Click OK.

  6. 6. Step 5 — Test the ZIP safely

    1. Copy the .zip to internal or SD storage.
    2. Boot into recovery (TWRP / OrangeFox).
    3. Install → select the ZIP → swipe to flash.
    4. Watch terminal logs — every ui_print line should output without errors.

  7. 7. Troubleshooting

    ProblemFix
    Error 7Wrong update-binary or corrupted ZIP. Ensure ZIP compression is Normal/Store.
    Invalid ZIP file zoneRe-zip; select items inside folder, not the folder itself.
    Partition not foundDifferent block path on A/B slots — use /dev/block/by-name/boot_a or boot_b.
    System files don't stick after rebootMissing unmount() before reboot, or partition read-only — verify dm-verity disabled.
