How to Disable DM-Verity & AVB on Android

Type
Advanced Guide
Level
Advanced
Time
~10 minutes
Applies to
Android 8+ devices with unlocked bootloader
Last updated
YYYY-MM-DD

Critical warning: disabling AVB/dm-verity requires an unlocked bootloader. On a locked device, this will brick the phone (red boot state). Also:

  • This weakens device security — only do it on your own device.
  • Unlocking the bootloader usually wipes all data.
  • Banking apps, Google Pay, and DRM content may stop working.

Modern Android uses Verified Boot (AVB) and dm-verity to cryptographically verify every partition before booting [citation:3][citation:5]. If you modify system.img, flash TWRP, or patch boot.img with Magisk, the hash no longer matches and the device refuses to boot — often showing a red warning or a boot loop. Disabling these checks via fastboot vbmeta flags solves this.

Reference

  1. 1. What are DM-Verity and AVB?

    FeatureWhat it verifiesWhat it blocks
    dm-verityBlock-by-block hashes of system, vendor, product partitions [citation:3]Modifying any file in /system
    AVB (Android Verified Boot)Whole-partition hashes + chained vbmeta signatures [citation:5]Flashing patched boot/recovery/TWRP

    Two fastboot flags control this inside the vbmeta partition:

    • --disable-verity → disables dm-verity hashtree (allows /system modifications)
    • --disable-verification → disables the entire AVB verification chain (allows any boot image)

    Which flag do you need? If you only want to run a patched boot image (Magisk root), you may not need either flag — the unlocked bootloader is enough. If you want to modify /system, you need --disable-verity. If you want to flash TWRP/custom recovery, you need --disable-verification [citation:16].

  2. 2. Prerequisites

    • Unlocked bootloader — check in Developer Options → OEM unlocking, then unlock via fastboot.
    • ADB & Fastboot installed on PC.
    • vbmeta.img extracted from your exact firmware build (or an empty/dummy vbmeta).
    • Charged battery and a quality USB cable.

    Firmware match: use the vbmeta.img from the same build number currently on your device. A mismatched vbmeta can cause baseband loss or boot failure.

  3. 3. Step 1 — Boot into Fastboot mode

    1. Enable USB Debugging on the phone.
    2. Connect to PC and run:
    adb reboot bootloader
    1. Verify the connection:
    fastboot devices

    You should see your device serial number.

  4. 4. Step 2 — Flash vbmeta with disable flags

    This is the core command. It rewrites the vbmeta partition with the disable flags set:

    fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img

    This single command is the standard method used by TWRP maintainers and the Magisk community [citation:1][citation:2].

    For A/B slot devices (most Android 10+ phones), flash both slots:

    fastboot --disable-verity --disable-verification flash vbmeta_a vbmeta.img
fastboot --disable-verity --disable-verification flash vbmeta_b vbmeta.img

    For devices with separate vbmeta partitions (some OEMs):

    fastboot --disable-verity --disable-verification flash vbmeta_system vbmeta_system.img
fastboot --disable-verity --disable-verification flash vbmeta_vendor vbmeta_vendor.img

  5. 5. Step 3 — Reboot

    fastboot reboot

    The device may show an "Orange State" or "Bootloader Unlocked" warning for a few seconds — this is normal and cosmetic.

    If it bootloops: some devices require a data wipe after disabling verity. Reboot to recovery and factory reset, or run fastboot -w (wipes userdata).

  6. 6. Alternative — Empty / Dummy vbmeta

    Some technicians use an empty vbmeta (a pre-built image with all verification flags cleared). This is useful when you don't have the stock vbmeta or want to skip flag parsing:

    fastboot --disable-verity --disable-verification flash vbmeta vbmeta-empty.img

    Empty vbmeta images are device-agnostic and work on most Qualcomm/MediaTek devices with unlocked bootloader [citation:14].

    Risk: empty vbmeta removes all verification. Only use if you accept that the device cannot detect corruption. Do not use on devices you rely on for security-sensitive work.

  7. 7. Verification — did it work?

    Method A — Check boot state:

    fastboot getvar all | grep -i verity
fastboot getvar all | grep -i verified

    You should see verity: disabled or verification: disabled.

    Method B — Mount /system read-write (if rooted):

    adb root
adb remount
adb shell mount | grep system

    If it shows rw (not ro), verity is off.

    Method C — Flash TWRP: if TWRP boots without bootloop, AVB is disabled successfully.

  8. 8. Common scenarios & what to do

    ScenarioFlags needed
    Flash Magisk-patched boot.imgNone (unlocked bootloader is enough)
    Modify /system/app files--disable-verity only
    Install TWRP / custom recovery--disable-verification
    Install custom ROM (LineageOS, etc.)--disable-verification
    Flash patched system.imgBoth flags

  9. 9. Troubleshooting

    ProblemFix
    Bootloop after disablingSome devices need fastboot -w (wipes data). Back up first.
    "FAILED (remote: unknown command)"Outdated fastboot. Download latest Platform Tools from Google.
    "FAILED (remote: not allowed)"Bootloader is still locked. Unlock it first.
    "FAILED (remote: Flashing is not allowed in Lock State)"Same — bootloader locked.
    Orange/red state warning at every bootCosmetic — unlock state is permanent. Cannot be removed without re-locking.
    TWRP boots but system won'tYou flashed vbmeta but not the patched boot/recovery. Flash TWRP or custom ROM first.
    Baseband becomes "Unknown" after flashvbmeta mismatch caused modem partition corruption. Re-flash stock firmware + modem.
    Device shows "Your device is corrupt"vbmeta flags not properly applied. Re-run the flash command and reboot.

  10. 10. Command cheat sheet

    # Enter Fastboot
adb reboot bootloader
fastboot devices

# Flash vbmeta with disable flags (A-only)
fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img

# Flash vbmeta with disable flags (A/B)
fastboot --disable-verity --disable-verification flash vbmeta_a vbmeta.img
fastboot --disable-verity --disable-verification flash vbmeta_b vbmeta.img

# Flash vbmeta_system / vbmeta_vendor (some OEMs)
fastboot --disable-verity --disable-verification flash vbmeta_system vbmeta_system.img
fastboot --disable-verity --disable-verification flash vbmeta_vendor vbmeta_vendor.img

# Empty vbmeta (all verification off)
fastboot --disable-verity --disable-verification flash vbmeta vbmeta-empty.img

# Reboot
fastboot reboot

# Wipe data if bootloop
fastboot -w

# Check flags
fastboot getvar all | grep -i verity

  11. 11. Best practices

    • ✅ Always use the exact matching vbmeta.img from your current build.
    • ✅ Back up EFS/NVRAM before any vbmeta flash (see related guides).
    • ✅ Flash both A/B slots to avoid slot-switch bootloops.
    • ✅ Test with TWRP first — if TWRP boots, AVB is disabled correctly.
    • ✅ Keep a copy of the original stock vbmeta for restoration.
    • ✅ If banking apps fail after unlock, use Magisk + Universal SafetyNet Fix.
    • ✅ Do not use on devices you didn't purchase yourself.

Tip: after disabling AVB, immediately flash TWRP or a patched boot image. Otherwise the next OTA update may re-enable verification and cause a bootloop. Also note: --disable-verity is the smaller flag (only disables dm-verity hashtrees), while --disable-verification is the larger flag (disables the entire AVB chain) [citation:16]. Use the smallest flag that works for your goal.
