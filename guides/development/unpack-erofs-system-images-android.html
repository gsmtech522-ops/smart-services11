How to Unpack EROFS System Images on Android

Type
Step-by-Step Guide
Level
Advanced
Time
~15 minutes
Applies to
Android 11+ devices with EROFS system/vendor partitions (Huawei, Honor, many modern SoCs)
Last updated
YYYY-MM-DD

Starting with Android 11, many manufacturers (especially Huawei/Honor) ship system.img and vendor.img as EROFS (Enhanced Read-Only File System) instead of ext4. EROFS is optimized for read-only performance and compression — but it cannot be mounted read-write or extracted with 7-Zip. You need erofs-utils on Linux or WSL to unpack and repack it [citation:1][citation:5].

Reference

  1. 1. Identify if your image is EROFS

    Check the magic bytes with a hex editor or PowerShell:

    $bytes = [System.IO.File]::ReadAllBytes("C:\firmware\system.img")[1024..1027]
[System.BitConverter]::ToString($bytes)

    If the output is E2-E1-F5-E0 at offset 1024, the image is EROFS. If it is 53-EF, it is ext4 — use the ext4 guide instead.

  2. 2. Prerequisites

    • Linux environment — Ubuntu 20.04+ (native or WSL2). EROFS tools are not available for native Windows.
    • erofs-utils package installed.
    • At least 5–10 GB free disk for the extracted filesystem.
    • The system.img extracted from your firmware package (or from super.img via lpunpack).

    Install erofs-utils:

    sudo apt update
sudo apt install erofs-utils -y

    Verify the tools:

    fsck.erofs --version
mkfs.erofs --version
dump.erofs --version

  3. 3. Step 1 — Inspect the EROFS image (optional)

    Before extracting, you can analyze the image structure:

    dump.erofs system.img

    This shows superblock info, compression algorithm, block size, and file count — useful for verifying the image is not corrupted [citation:1][citation:8].

  4. 4. Step 2 — Extract the EROFS image with fsck.erofs

    fsck.erofs is the official extraction tool. It verifies integrity and extracts all files [citation:7][citation:12].

    mkdir -p extracted_system
sudo fsck.erofs --extract=./extracted_system system.img

    Options explained:

    • --extract=DIR — extract to the specified directory.
    • --no-preserve — skip preserving UID/GID/permissions (useful on WSL where you are not root).
    • --overwrite — overwrite existing files in the output directory.
    • --no-sbcrc — skip superblock checksum verification (use only if the image fails checksum due to modification).

    Recommended command for WSL (non-root):

    sudo fsck.erofs --extract=./extracted_system --no-preserve --overwrite system.img

    Note: fsck.erofs extraction is single-threaded and can be slow on large images. Extended attributes (xattrs) are not extracted by default — add --xattrs if you need SELinux contexts [citation:1][citation:12].

  5. 5. Step 3 — Explore and modify the extracted filesystem

    After extraction, you get a directory tree identical to the original /system partition:

    extracted_system/
├── app/
├── bin/
├── etc/
├── framework/
├── lib/
├── lib64/
├── priv-app/
├── build.prop
└── ...

    You can now add, remove, or modify files directly in this directory.

  6. 6. Step 4 — Repack the EROFS image with mkfs.erofs

    After modifications, rebuild the EROFS image:

    mkfs.erofs -zlz4hc -Enoinline_data system_new.img ./extracted_system

    Common flags:

    • -z lz4hc — use LZ4 HC compression (most Android devices use this) [citation:4][citation:13].
    • -E noinline_data — disable inline data for better compatibility with older kernels.
    • --file-contexts=plat_file_contexts — include SELinux file contexts (required if your device uses SELinux and you modified files) [citation:10].
    • -T <timestamp> — set a fixed timestamp for reproducible builds.

    Example with SELinux contexts (recommended for stock ROMs):

    mkfs.erofs -zlz4hc \
  --file-contexts=./plat_file_contexts \
  system_new.img ./extracted_system

    File contexts: if you do not include --file-contexts, the repacked image will be missing SELinux labels, and the device may fail to boot or show permission errors. Extract plat_file_contexts from the original firmware or the device's /system/etc/selinux/ before repacking [citation:10].

  7. 7. Step 5 — Verify and flash

    Verify the new image:

    file system_new.img
dump.erofs system_new.img

    Output should confirm: EROFS filesystem with your chosen compression.

    Flash the image:

    • For devices with super.img (dynamic partitions): repack into super.img with lpmake, then flash via fastboot.
    • For devices with direct system partition: fastboot flash system system_new.img.
    • For SP Flash Tool / Odin: convert to sparse with img2simg if required by the tool.

  8. 8. Troubleshooting

    ProblemFix
    fsck.erofs: command not foundInstall erofs-utils package. On WSL, run sudo apt install erofs-utils.
    Extraction fails with "invalid magic"Image is not EROFS, or is truncated. Re-extract from the firmware.
    Extraction fails on WSL with permission errorsUse --no-preserve to skip UID/GID preservation.
    Repacked image fails to bootMissing --file-contexts (SELinux). Rebuild with the correct contexts file.
    Repacked image is much larger than originalUse -zlz4hc with a high level (e.g. -zlz4hc,12), or check that the original used a different compression algorithm.
    Device bootloop after flashing EROFS imagedm-verity/AVB is rejecting the modified image. Disable verity/vbmeta first, or re-sign the image if you have OEM keys.
    Cannot mount EROFS image on WindowsEROFS is Linux-only. Use WSL2 or a Linux VM.

  9. 9. Complete command reference

    # ---- Install tools ----
sudo apt install erofs-utils -y

# ---- Inspect ----
dump.erofs system.img

# ---- Extract ----
mkdir -p extracted_system
sudo fsck.erofs --extract=./extracted_system system.img

# For WSL (non-root):
sudo fsck.erofs --extract=./extracted_system --no-preserve --overwrite system.img

# With xattrs (SELinux contexts):
sudo fsck.erofs --extract=./extracted_system --xattrs system.img

# ---- Repack ----
mkfs.erofs -zlz4hc system_new.img ./extracted_system

# With SELinux file contexts:
mkfs.erofs -zlz4hc --file-contexts=./plat_file_contexts system_new.img ./extracted_system

# ---- Verify ----
file system_new.img
dump.erofs system_new.img

# ---- Flash (fastboot) ----
fastboot flash system system_new.img

# ---- Convert to sparse (if needed for SP Flash Tool/Odin) ----
img2simg system_new.img system_sparse.img

  10. 10. Best practices

    • ✅ Always work on a copy of the original image.
    • ✅ Use dump.erofs first to confirm the image is valid and check compression type.
    • ✅ On WSL, always use --no-preserve to avoid permission errors.
    • ✅ Include --file-contexts when repacking stock ROMs — otherwise SELinux will block files at boot.
    • ✅ Match the original compression algorithm (lz4hc is most common on Android).
    • ✅ Test on a non-critical device first if possible.
    • ✅ Back up EFS/NVRAM before flashing any modified system image.

Tip: EROFS is read-only by design — you cannot mount it read-write like ext4. The extract → modify → repack workflow is the only way to change files inside an EROFS system.img. If your device uses super.img (dynamic partitions), first extract system.img with lpunpack, then follow this guide [citation:5][citation:9].
