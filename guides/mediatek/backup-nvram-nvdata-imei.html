Backup & Restore MTK NVRAM, NVDATA and IMEI

Type
Critical Backup Guide
Level
Advanced
Time
~15 minutes
Applies to
All MediaTek devices
Last updated
YYYY-MM-DD

On MediaTek devices, system partitions (system, vendor) hold the OS, but critical security data — IMEI numbers, Wi-Fi MAC, Bluetooth MAC, baseband calibration — lives in nvram and nvdata. If these get wiped, you get:

  • "Invalid IMEI" or "IMEI Null" errors
  • "NVRAM WARNING: Err = 0x10" in Wi-Fi settings
  • No network signal / Emergency calls only

Legal note: only back up and restore your own device's NVRAM/IMEI. Modifying IMEI is illegal in most countries. This guide is for backup/restore only — not modification.

Reference

  1. 1. Key security partitions

    PartitionFunction
    nvramPrimary calibration, IMEI structure, Wi-Fi/BT MAC
    nvdataRuntime cellular data and dynamic radio settings
    nvram_bt / nvram_wifiBluetooth/Wi-Fi configuration tables (modern Helio)
    seccfgBootloader lock state
    protect1 / protect2SIM lock info and radio frequency tuning

  2. 2. Method 1 — Backup via SP Flash Tool (scatter method)

    1. Open SP Flash Tool, load your scatter file.
    2. Open the scatter in Notepad, search for partition_name: nvram and nvdata.
    3. Note each partition's physical_start_addr and partition_size.
    4. Switch to Readback tab, click Add.
    5. Add two entries:
      • Entry 1 → nvram.bin with nvram addresses
      • Entry 2 → nvdata.bin with nvdata addresses
    6. Click Readback, power off, connect with volume keys held.

    To restore via SP Flash Tool: enable Advanced Mode (Ctrl+Alt+V), use Write Memory to write nvram.bin and nvdata.bin back to their original addresses.

  3. 3. Method 2 — One-click via MTKClient (recommended)

    MTKClient auto-detects partitions — no hex addresses needed.

    1. Open CMD inside your mtkclient folder.
    2. Power off the phone and connect with volume keys held (BROM mode).
    3. Dump the security partitions:
    python mtk r nvram,nvdata,protect1,protect2,seccfg nvram_backup/

    To restore:

    python mtk w nvram,nvdata,protect1,protect2,seccfg nvram_backup/nvram.bin,nvram_backup/nvdata.bin,nvram_backup/protect1.bin,nvram_backup/protect2.bin,nvram_backup/seccfg.bin

  4. 4. Method 3 — ADB shell (rooted device)

    If the phone is rooted and powered on:

    adb shell su
dd if=/dev/block/by-name/nvram of=/sdcard/nvram.img
dd if=/dev/block/by-name/nvdata of=/sdcard/nvdata.img
exit
adb pull /sdcard/nvram.img C:\MTK_Security_Backup\
adb pull /sdcard/nvdata.img C:\MTK_Security_Backup\

    To restore:

    adb shell
su
dd if=/sdcard/nvram.img of=/dev/block/by-name/nvram
dd if=/sdcard/nvdata.img of=/dev/block/by-name/nvdata
reboot

  5. 5. ⚠️ Golden rule for MTK technicians

    Never use "Format All + Download" in SP Flash Tool without first backing up nvram and nvdata. Full erase without a security dump wipes your device's factory IMEI and network calibration permanently.
