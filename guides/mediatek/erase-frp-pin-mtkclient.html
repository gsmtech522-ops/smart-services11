Erase FRP and PIN/Pattern Locks using MTKClient

Type
Advanced Guide
Level
Advanced
Time
~5 minutes
Applies to
Modern Helio P/G and Dimensity devices
Last updated
YYYY-MM-DD

Legal warning: only for your own device or a device you are explicitly authorized to service. Bypassing FRP or screen locks on another person's phone is illegal and can be traced.

Modern MediaTek devices enforce SLA/DAA authentication that blocks traditional tools. MTKClient exploits BROM vulnerabilities to erase FRP and screen lock partitions without paid dongles or .auth files.

Reference

  1. 1. Prerequisites

    • MediaTek VCOM drivers + UsbDk drivers installed.
    • Python 3.9+ with "Add to PATH" enabled.
    • Git installed (or MTKClient zip downloaded).
    • Charged device + USB cable.

    Install MTKClient:

    git clone https://github.com/bkerler/mtkclient.git
cd mtkclient
pip install -r requirements.txt

  2. 2. Target partitions

    • frp — Google Account Factory Reset Protection
    • userdata — encrypted user data, PIN/pattern/password
    • metadata — encryption key metadata (must wipe with userdata)
    • md_udc — modem user data cache

  3. 3. Method 1 — CLI (recommended)

    1. Open CMD inside mtkclient folder.
    2. Power off the device.
    3. Erase FRP only:
    python mtk e frp
    1. Erase FRP + all screen locks:
    python mtk e metadata,userdata,md_udc,frp
    1. Terminal shows Waiting for device...
    2. Hold Volume Up+Volume Down (or Volume Down only on some models) and plug USB.
    3. MTKClient exploits BROM, erases partitions, shows Success.
    4. Unplug and boot.

  4. 4. Method 2 — GUI

    1. Launch GUI:
    python mtk_gui
    1. Power off, hold volume keys, plug USB to enter BROM.
    2. Once SoC detected (e.g. MT6765, MT6833), go to Flash Tools tab.
    3. Click Erase Userdata or Format Data for screen locks.
    4. Click Erase FRP for Google lock.
    5. Wait for green success banner.
    6. Unplug and reboot.

  5. 5. Troubleshooting

    UsbDk missing / device disconnects instantly

    Cause: Windows drops BROM handshake before MTKClient sends payload.

    Fix: install latest UsbDk 64-bit installer, reboot PC.

    Charging mode instead of BROM

    Cause: boot keys released too early, or preloader intercepted boot.

    Fix: disconnect, hold Power 10s to reset, hold boot keys firmly, then insert cable while running command.

    Device hangs on logo after wipe

    Cause: wiped userdata without metadata — stale crypto footers confuse init.

    Fix: run python mtk e metadata,userdata,md_udc, then boot into stock recovery and perform Wipe Data.
