Unlock MediaTek Bootloader via BROM Mode

Type
Advanced Guide
Level
Advanced
Time
~10 minutes
Applies to
MediaTek Helio P/G series & Dimensity chipsets
Last updated
YYYY-MM-DD

Legal warning: only unlock the bootloader of your own device. Bypassing OEM waiting periods on someone else's phone, or using this to install malicious firmware, is illegal in most countries. Unlocking voids warranty and forces a factory reset.

Unlocking the bootloader on modern Android devices normally requires enabling the OEM Unlocking toggle, issuing fastboot commands, requesting authorization from manufacturer servers, or waiting through cooling-off periods (7–14 days). On MediaTek devices, Boot ROM (BROM) exploitation lets technicians bypass the OS entirely by patching the seccfg partition directly — instantly unlocking the bootloader without OEM approval tokens.

Reference

  1. 1. Prerequisites & environment setup

    • MediaTek VCOM USB drivers & UsbDk drivers installed on Windows PC.
    • Python 3.9+ with "Add Python to PATH" enabled.
    • MTKClient downloaded or cloned on PC.
    • Target MediaTek smartphone (Helio or Dimensity) + quality USB data cable.
    • Full backup of personal data — unlocking forces an automatic factory reset of userdata.

    Install MTKClient:

    git clone https://github.com/bkerler/mtkclient.git
cd mtkclient
pip install -r requirements.txt

    Install UsbDk (once):

    • Download the 64-bit UsbDk.msi from the official GitHub releases.
    • Run installer → reboot PC.

  2. 2. Understanding the seccfg partition

    MediaTek bootloader security relies on an encrypted hardware flag stored in the seccfg partition (Security Configuration). On power-on, the preloader verifies this block to decide whether untrusted images (custom recoveries, patched boot, modified system) can execute.

    Instead of requesting an encrypted unlock key signed by the vendor, BROM exploits let MTKClient inject a custom payload into SRAM, forcing the preloader to write a valid "unlocked" signature into seccfg — permanently toggling bootloader security off at the hardware layer.

    Why this works: BROM runs before any Android verification. Exploiting it bypasses the OEM's unlock-request flow entirely, because the check that would reject the OEM token hasn't been reached yet .

  3. 3. Step 1 — Put the device into BROM mode

    1. Ensure battery connections are stable, then power off the device completely.
    2. Open Command Prompt, PowerShell, or Terminal inside your mtkclient directory.
    3. Initiate the unlock sequence:
    python mtk da-xml unlock
    1. The terminal prints: Waiting for device in BROM mode...
    2. Press and hold the boot keys — usually Volume Up+Volume Down or Volume Down only.
    3. Plug in the USB cable while holding the keys. Once the PC detects the MTK BROM COM port, release the buttons.

    Note: some devices enter Preloader mode instead of BROM. If MTKClient hangs on "waiting for device" for more than 5 seconds, unplug, hold Power+Volume Down for 10s to hard reset, then retry with both volume keys held.

  4. 4. Step 2 — Execute instant BROM unlock

    For a clean single-flow trigger that handles both the auth bypass and the lock-flag modification:

    python mtk e metadata,userdata,md_udc
python mtk da-xml unlock
    1. MTKClient exploits the Boot ROM, disables SLA/DAA security payloads, and modifies the seccfg signature block.
    2. Terminal shows progress:
    Bypass SLA/DAA success.
Sending payload...
Patching seccfg partition...
Writing unlocked header to target block... Success!
    1. Disconnect USB when complete.

  5. 5. Step 3 — Post-unlock & first boot

    1. Power on the phone by holding Power.
    2. During boot, a warning screen appears — "Orange State: Your device has been unlocked and cannot be trusted". This confirms the unlock succeeded.
    3. First boot after unlock takes 2–5 minutes (new userdata encryption keys generated).
    4. Complete the initial Android setup wizard.

    Orange State warning is permanent until the bootloader is re-locked. It is purely cosmetic and does not affect functionality.

  6. 6. Relock the bootloader via BROM (optional)

    To restore factory lock status for warranty or stock OTA updates:

    python mtk da-xml lock

    This re-signs seccfg with the "locked" flag. Note that data will be wiped again.

  7. 7. Troubleshooting

    1. Device stuck in Preloader mode / handshake timeout

    Cause: phone boots straight into Preloader or Charging mode before BROM exploitation initializes.

    Fix: install UsbDk drivers, reboot PC, hold both volume keys firmly before plugging USB. On some modern MTK devices, a hardware test point (shorting CLK to GND) is required if BROM is soft-disabled by the OEM preloader.

    2. Red State: "Your device has failed verification" bootloop

    Cause: seccfg was patched but userdata or vbmeta signatures are corrupted.

    Fix: erase metadata and userdata via MTKClient:

    python mtk e metadata,userdata

    Or re-flash stock vbmeta.img with disable flags via fastboot:

    fastboot flash --disable-verity --disable-verification vbmeta vbmeta.img

    3. Error: Verified Boot is enabled (AVB)

    Cause: Android Verified Boot (AVB 2.0) blocks modified boot images after unlocking.

    Fix: flash a blank or patched vbmeta via MTKClient or fastboot:

    fastboot flash --disable-verity --disable-verification vbmeta vbmeta.img

  8. 8. Additional troubleshooting table

    ProblemFix
    LIBUSB_ERROR_NOT_SUPPORTEDInstall UsbDk 64-bit, reboot PC.
    Device not detected at allMTK VCOM driver missing — install from the drivers guide.

    "seccfg partition not found"Some devices use seccfg_a/seccfg_b for A/B slots. MTKClient handles this automatically in newer versions.

  9. 9. Complete command reference

    # ---- Setup (once) ----
git clone https://github.com/bkerler/mtkclient.git
cd mtkclient
pip install -r requirements.txt

# ---- Unlock bootloader ----
python mtk da-xml unlock

# ---- Clean erase + unlock (recommended) ----
python mtk e metadata,userdata,md_udc
python mtk da-xml unlock

# ---- Relock bootloader (wipes data) ----
python mtk da-xml lock

# ---- Check current lock state (advanced) ----
python mtk r seccfg seccfg.img
xxd seccfg.img | head

# ---- Alternative method — direct seccfg write ----
# 1. Dump seccfg
python mtk r seccfg seccfg.img

# 2. Patch seccfg with a known-good unlocked image
python mtk w seccfg unlocked_seccfg.img

# ---- Fix AVB after unlock ----
fastboot flash --disable-verity --disable-verification vbmeta vbmeta.img

# ---- Erase userdata only (fix Red State) ----
python mtk e metadata,userdata

  10. 10. Best practices

    • ✅ Only unlock your own device — unlocking someone else's phone is illegal.
    • ✅ Full data backup first — unlock always wipes userdata.
    • ✅ Install UsbDk before trying — it prevents most detection failures.
    • ✅ Use a USB 2.0 port on the motherboard, not front-panel hubs.
    • ✅ After unlock, immediately flash TWRP or custom recovery if that's your goal — leaving the bootloader unlocked with no custom recovery adds no value.
    • ✅ Keep a working seccfg.img backup in case you need to restore the original state.
    • ✅ If you ever RMA the device, relock the bootloader first.

Tip: MTKClient can also dump your seccfg.img as a backup. If something goes wrong during a future operation, you can restore it with python mtk w seccfg seccfg_backup.img to reset the bootloader state.
